# Численные ядра

Всё ниже обязательно и проверяемо: часть ловит компилятор, часть — grep в хуке,
остальное — тест.

## Форма ядра (ADR-015)

Ядро пишется сразу в форме, переводимой в WGSL **построчно**. Не «потом
перепишем» — с первой строки.

Сигнатура фиксирована (ADR-034); она и оба скелета — диффузия и реакции — в
`docs/ARCHITECTURE.md`. Читай оба: на диффузии форма выглядит очевидной, и всё,
что в ней неочевидно, видно только на реакциях.

```rust
fn kernel(src: &[..], dst: &mut [..], p: &Params, idx: u32)
```

Разрешено:

- функции над плоскими массивами, индексация по линейному индексу вокселя;
- обработка вокселя, независимая от порядка обхода;
- локальные скаляры, массивы фиксированного размера, `for` по диапазону.

Запрещено внутри ядра:

- `self`, трейты, трейт-объекты, дженерики по поведению;
- аллокации в цикле — вообще любые аллокации;
- замыкания, `Vec`, `HashMap`, `Box`, `dyn`, рекурсия;
- ветвление по типу и вызовы через таблицу виртуальных методов;
- знание про конфиг, время и `dx` по отдельности: параметры сворачиваются на
  хосте и приходят одним числом;
- зависимость результата от порядка обхода вокселей (двойная буферизация
  обязательна: читаем состояние `N`, пишем `N+1`).

CPU-версия — вечный эталон, а не строительные леса. После порта на GPU она
остаётся: расхождение шейдера с ней в целочисленных полях есть баг в шейдере.

## Gather, а не scatter (ADR-034)

Воксель считает своё новое значение сам, читая соседей, и пишет **только в свою
ячейку**. Никогда в чужую.

ADR-005 формулирует сохранение как «вычли у донора, прибавили акцептору», и
напрашивается ядро, применяющее поток к обеим ячейкам. Так нельзя: на GPU это
атомик на каждую грань, а результат становится зависимым от порядка.

В gather-форме сохранение следует из антисимметрии функции потока:

```
flux(a, b) == −flux(b, a)   при любых a и b
```

Сосед в том же подшаге прибавит себе ровно противоположное, сумма по домену
тождественно ноль — без атомиков и без синхронизации.

**Антисимметрия держится на правиле округления.** Половины от нуля симметричны:
`1.5 → 2`, `−1.5 → −2`. Округление вниз — нет: `floor(1.5) = 1`, но
`floor(−1.5) = −2`. Написать поток через `floor` — самый естественный способ
округлить целочисленный сдвиг, — и масса потечёт по единице на грань. Ни
компилятор, ни grep этого не увидят; ловит только тест
`flux_is_antisymmetric`, и он обязателен для каждой новой функции потока.

Единственное исключение из «пиши только в свою ячейку» — счётчики каналов
ledger: атомарное сложение, коммутативное, потому что счётчики целые.

Сохранение обязано быть верным **по построению**, а не выполняться приближённо
и проверяться тестом. Если схему можно записать так, что масса теряется, схема
неправильная.

## Никаких голых операторов над `Q` (ADR-022)

`M` — экстенсивные, учитываемые величины: количества веществ, энергия, объём.
Всегда целые. Единица учёта вещества молярная — `units_per_mol` (ADR-026);
килограммы остались только в плотности, объёме и оседании.
`Q` — интенсивные и производные: концентрации, температура, скорости реакций,
экспрессия, коэффициенты, промежуточные результаты. Режимо-зависимые.

Внутри ядра над `Q` **нет голых арифметических операторов**. Только обёртки:

```
qadd  qsub  qmul  qdiv
qexp  qlog  qpow  qsqrt  qrcp  qsigmoid
```

Конверсия между классами происходит ровно в трёх местах и больше нигде
(`NUMERIC.md` §1):

```
q_conc(amount: M, volume)        -> Q        количество в концентрацию
m_delta(rate: Q, dt)             -> M        скорость в приращение количества
xi(rate: Q, dt, volume, e_r, rng) -> integer скорость в число квантов экстента
```

Первые две — для переноса и для всего, что списывается непрерывно. Третья
единственная работающая в реакциях: там округления по веществам быть не должно
вовсе, изменения получаются как `νᵢ · ξ` при целых `νᵢ`, и округляется только
`ξ`, стохастически (ADR-027).

Причина, по которой правило жёсткое, а не рекомендательное: смена режима
`FLOAT`/`FIXED` должна стоить пересборки, а не переписывания ядер. Один голый
`a * b` в горячем месте — и в fixed-режиме там тихо неверный результат вместо
ошибки компиляции. Трансцендентные обязаны быть таблицами: IEEE-754 не требует
побитовой точности для `exp`, `log`, `pow`, и реализации у вендоров расходятся.

Первый рубеж защиты — сам тип: `Q` не реализует `Deref` и не раскрывает
внутреннее поле, поэтому голый оператор не компилируется. Второй рубеж — grep в
`kernel-lint`-хуке и в CI, для WGSL-шаблонов, где системы типов нет.

Таблица операций и правило округления — `docs/NUMERIC.md`.

## Разрядность хранения выводится, а не назначается (ADR-040)

Количество вещества хранится в `i32` или `i64`, и что именно — решает валидатор
при загрузке из объявленных `typical_conc` и `max_conc`, а не автор ядра. В
нынешнем реестре 64-битное вещество ровно одно, вода; остальные тринадцать
32-битные.

Следствия, которые обязаны быть в ядре с первой строки:

- `amount[]` не однородный массив. Разноширинность живёт в двух срезах и битовой
  маске `width_mask` в `Params` (бит `s` — вещество `s` в `i64`), доступ идёт
  через две функции и больше нигде;
- ветвление по этой маске идёт **по индексу вещества**, одинаковому для всех
  вокселей. На GPU это uniform-переход; ветвление по вокселю расходило бы варп;
- бесплатного `i64` нет: в базовой спецификации WGSL 64-битных целых не
  существует, этот путь эмулируется парой `u32`. Поэтому он генерируется
  шаблоном на сборке, второй осью того же генератора, что режимы `FLOAT`/`FIXED`
  (`NUMERIC.md` §5), а не пишется руками вторым файлом.

### Полоса — не индекс вещества (ADR-056)

Индекс вещества разрешается в пару «ширина хранения, полоса», причём полоса
нумеруется **внутри своего класса ширины**. Отсюда правило, а не наблюдение:

```
lane != s              — везде, по правилу, а не по случайности
s * n_voxels + idx     — баг внутри ядра, всегда
```

Адрес считается только через таблицу, которая приходит вместе с реакциями:

```rust
let at = (rx.lane[s as usize] * p.n_voxels + idx) as usize;
```

Таблица идёт в `Rx`, а не в `Params`: в `Params` только скаляры, в WGSL это
uniform-буфер.

Правилом, а не наблюдением — потому что нарушение молчаливо. Ядро, адресующее
по индексу вещества, читает полосу, принадлежащую другому веществу; ledger
сходится, потому что ничего не потеряно — прочитано не то. Хуже: на реестре,
который проект действительно носит, вода стоит первой и берёт полосу 0, поэтому
неверное выражение **верно** при `s == 0` и промахивается на единицу дальше.

Таблица полос — не единственная, у кого своя индексация. `conc_per_unit`
индексируется **веществом**, как и `lane`, а `nu`, `nu_sub` и `km` —
**записью**; буферы количеств — полосой. Спутать `conc_per_unit` с таблицей по
полосам значит сдвинуть концентрацию на `2^(kᵢ − kⱼ)`, то есть на десятки
двоичных порядков в скорости, — и баланс сойдётся точно, потому что скорость не
входит ни в один инвариант.

Ловят это двое. Тест `mixed_width_storage_matches_uniform_width_storage`
(`tests/acceptance_reactions.rs`) гоняет ядро на разноширинном реестре и на
искусственно одноширинном и требует совпадения. И grep в `kernel-lint`: он
ругается на умножение **идентификатора** на `n_voxels`, потому что законный
адрес умножает на него элемент таблицы полос. Проверка сознательно неполна —
`let lane = rx.lane[s as usize];` с последующим `lane * p.n_voxels` она
пропускает, и правильно делает: это законная запись. Полноту даёт тест.

## Ядро реакций (ADR-041)

Реакция локальна: ядро реакций не читает соседей, не пишет ни в один чужой
воксель и не трогает счётчики каналов вовсе — суммы для ledger берутся редукцией
в фазе LEDGER. Исключением про атомики из ADR-034 оно не пользуется.

Все реакции вокселя считают спрос по одному снимку состояния `N`, конкурируют за
субстрат общим коэффициентом и записываются одним применением в `N+1`. Пересчёт
наличия после каждой реакции делает порядок строк в TOML частью семантики мира —
невидимо, потому что баланс продолжает сходиться. Дельты копятся в локальном
массиве и пишутся один раз: `dst[at] += …` внутри цикла по реакциям есть чтение
из буфера записи.

Отсюда две константы сборки: локальные массивы обязаны быть фиксированного
размера, значит их размер приходится назвать. `S_MAX = 32` — веществ, согласовано
с `width_mask: u32`; `R_MAX = 64` — реакций. Валидатор отвергает конфиг, который
их превысил, называя обе величины. «Реестр — данные» (ADR-018) после этого
означает «данные в пределах объявленной границы».

Скелет со всеми тремя несущими местами — `docs/ARCHITECTURE.md`.
