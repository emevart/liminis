# Схема конфига сценария

## Рабочий Локальный Сценарий (2026-10-04)

`configs/scenarios/genetic-colony.toml` запускается через `liminis serve` без
дополнительных аргументов (ADR-095). Явные `--config`, `--seed` и `--port`
сохраняются. Прежний `configs/scenarios/living-world.toml` выбирается явно;
это некалиброванная культура пяти конечных экотипов (ADR-091, ADR-092),
а не реализация всей исследовательской модели S1.

В этой реализации `catalyst = "guild:<id>"` разрешается при сборке `React` в
существующий `[[substance]].id`. Его текущая молярная концентрация умножает
скорость реакции. Отдельный счётчик биомассы не создаётся; несуществующий `id`
отвергается. `expr:<k>`, непустые `requires` и `energy_from` пока не поддержаны.
Наследуемые стратегии и мутационные ветви задаются обычными реакциями TOML.

`reactions` должен быть явно включён. Проверка фактического `max_conc`
работает перед и после каждого тика в debug и release; выход за объявленный
предел останавливает локальный прогон с видимой ошибкой. Первый локальный этап
относился к версии мира 27; генетическая колония ниже использует
`WORLD_FORMAT_VERSION = 28`.

### Генетическая Колония (ADR-093, ADR-094)

`configs/scenarios/genetic-colony.toml` задаёт один сферический очаг G00,
четыре возможных двухбитных генотипа и два ресурсных пути: FOOD и DET.
Это конечная популяционная генетика в полях концентраций, не отдельные клетки
и не открытая эволюция произвольных геномов.

| Ключ | Тип / единица | Проверка |
|---|---|---|
| `genetics.prefix` | непустая строка | генерирует идентификаторы `<prefix>00` ... `<prefix>11` |
| `genetics.mutation_probability` | доля, `[0, 1]` | только потомство; неизменённый геном `1-p`, каждый однобитный сосед `p/2` |
| `genetics.preferred_fraction` | доля, `[0, 1]` | две аллокации суммируются в 1; бит 1 меняет их местами |
| `genetics.fast_vmax_factor` | безразмерный, `> 1` | бит 0 увеличивает темп роста |
| `genetics.fast_km_factor` | безразмерный, `> fast_vmax_factor` | цена быстрого роста: худшее сродство к назначенному ресурсу |
| `genetics.biomass` | шаблон `Substance` | placeholder не объявляется обычным веществом; четыре копии проходят общую проверку |
| `genetics.growth` | ровно два пути | разные `resource`; каждый присутствует во входах и `rate.km`; одна единица biomass в выходах |
| `genetics.turnover` | шаблон `Reaction` | потребляет biomass; его вход, Km и guild-катализатор разрешаются в родительский генотип |
| `initial.concentration.<id>` | `f64`, моль/м³ | известное вещество; конечное значение от 0 до `max_conc` |
| `initial.inoculum[].substance` | идентификатор вещества | известная дорожка реестра |
| `initial.inoculum[].center` | три координаты, м | сфера целиком внутри домена |
| `initial.inoculum[].radius` | положительное число, м | сфера содержит центр хотя бы одного вокселя |
| `initial.inoculum[].concentration` | `f64`, моль/м³ | от 0 до `max_conc`; переписывает концентрацию внутри сферы |

Начальное состояние строится в порядке: прежний стохастический фон,
равномерные переопределения, затем сферические переопределения. Для одного
вещества сферы не пересекаются; это исключает зависимость от порядка деклараций.
Количество переводится в целые единицы один раз при выводе параметров.

Шаблоны компилируются при загрузке в обычные вещества и реакции, до общей
валидации химии. Повторная материализация идемпотентна; конфликтующая ручная
запись с генерируемым id отвергается. Параметры генетики и начальных условий
входят в канонический `config_hash`. Публичный `decode_genotypes` используется
и компилятором, и observer API, поэтому расшифровка в UI не отдельная модель.

Имена шаблонов роста непусты и различны. Имя ветви рождения имеет форму
`<template_id>__<parent>_to_<child>`; перестановка записей не меняет её
идентификатор розыгрыша. Любая химия, затрагивающая генерируемые генотипы,
принадлежит компилятору: дополнительные или устаревшие строки отвергаются.
Исходные шаблоны также не могут напрямую ссылаться на генерируемые генотипы
во входах, выходах или Km; для биомассы используется только placeholder.
Иначе дополнительный выход мог бы обойти однолокусную мутацию.
Для изменения генов редактируется исходная декларация. Каноническая форма
с материализованными строками фиксирует точную идентичность эксперимента,
а не служит таблицей ручных переопределений.

Полный перечень ключей сценария: тип, единица, умолчание, решение, которое ключ
требует, и тест, который его стережёт.

Документ существует потому, что поверхность вклада без описания — это
приглашение угадывать. ADR-018 делает правку TOML всей поверхностью вклада:
реестры веществ, реакций и процессов объявлены данными, и если для нового
сценария приходится трогать Rust, это дефект архитектуры. `ACCEPTANCE.md`
перечисляет сорок отказов валидатора именами тестов — то есть сорок
проверок над схемой, которой не существует. Правило без таблицы непроверяемо
ровно так же, как в `QUANTITIES.md`.

Ключи сегодня разложены по SPEC §2.3 и §5, `QUANTITIES.md` и записям
ADR-025 … ADR-069. Собранные вместе они значат больше, чем порознь: половина
проверок связывает ключи из **разных** секций и называет виновника парой
«вещество, реакция», а не одним именем (ADR-039). Читая по одному документу,
эту связь увидеть нельзя — она возникает только на общей таблице.

Здесь нет решений. Всё, что записано, следует из `SPEC.md`, `DECISIONS.md`,
`QUANTITIES.md`, `NUMERIC.md` и `crates/liminis-core/src/config.rs`; расхождение
с ними — ошибка этого файла. Где решения нет, стоит `TODO` с адресом открытого
вопроса, а не правдоподобное число: ключ с угаданным значением выглядит в точности
как ключ с решённым, и валидатор эту разницу не восстановит. Все такие места
собраны в §13.

Загрузчик реализует сегодня три ключа из этой схемы — `name`, `dt` и `[grid]`.
Остальное — работа S0, а не расхождение документа с кодом. Один тест из
`ACCEPTANCE.md` смотрит на саму схему и ни на что другое:
`config_schema_declares_no_voxel_dependent_units`.

## 1. Как читать

**Обязателен** — умолчания нет, отсутствие ключа есть ошибка загрузки.

**TODO(A-NN)** — ключ обязан существовать, а значения в проекте нет. В скобках
адрес вопроса из `OPEN_QUESTIONS.md`. Такой сценарий не грузится, и это верно:
неназванная величина в конфиге хуже отсутствующей секции.

**выбор схемы** — имя ключа, его умолчание или группировка не названы ни одним
решением. Помечено там, где помечено, чтобы это не читалось как решение проекта.

Имя ключа — выбор схемы всякий раз, когда его не выписал ни SPEC, ни ADR.
Пометки в каждой такой строке нет, иначе она стояла бы почти везде; вместо этого
здесь полный список: `diffusivity`, `mu`, `beta`, `path`, `min`, `max`, `scale`,
имена граней в `[boundary]`, идентификаторы полей и процессов.
Реестр величин знает первые три как `D[i]`, `μ` и `β` — ASCII-запись
выбрана тут. Названы решениями: `conserved` (ADR-025, форма — ADR-064),
`molar_mass` (ADR-033), `typical_conc` и `max_conc` (ADR-039),
`partial_molar_volume` и `settling_radius` (ADR-067), `thermal_diffusivity`,
`t_min` и `t_max` (ADR-062), `conc_out`, `t_out` и `k_ex` (ADR-059),
`u_conv_max`, `l_c`, `stir_fraction` и `stir_period` (ADR-069), `theta_max`
(ADR-082), имя секции `[physics]` и ключи `g` и `rho_medium` (ADR-085). Выписаны
в SPEC: всё, что стоит в примере §5, `enabled`, `lod`, `k_w … k_m`; в
`config.rs` — `name`, `dt` и `[grid]`.

Одно имя в этом списке ещё не выбрано и помечено `TODO` там, где стоит:
идентификатор процесса поля скоростей. ADR-069 говорит «запись процесса поля
скоростей» и строки `id` не печатает, а идентификаторы процессов этот список
относит к выборам схемы (§7, §12). Второе, ASCII-запись `ρ_среды`, выбрано
ADR-085 — `rho_medium` в секции `[physics]` (§4а), — и вместе с ним закрылся
вопрос о значении и статусе `g`.

Единицы берутся из `QUANTITIES.md`. Там, где SPEC приводит ту же величину в
другой единице, это названо явно: молчаливый множитель в тысячу и есть тот класс
ошибок, ради которого реестр величин заведён.

## 2. Корень сценария

| Ключ | Тип | Единица | Обязателен / умолчание | Откуда | Стережёт |
|---|---|---|---|---|---|
| `name` | строка | — | обязателен | `config.rs` | — |
| `dt` | `f64` | с | `1.0` | ADR-030, QUANTITIES §1 | `courant_violation_is_rejected`, `every_n_ticks_on_diffusive_field_is_rejected` |
| `beta` | `f64` | — (доля типичного пула) | `0.015625` = 2⁻⁶ | ADR-039 | `reaction_with_unrepresentable_concentration_spread_is_rejected`, `stoichiometry_in_storage_units_fits_i32` |
| `T_ref` | `f64` | К | обязателен | ADR-044, ADR-062 | `temperature_from_enthalpy_round_trips`, `t_ref_outside_the_declared_temperature_range_is_rejected` |
| `conserved` | таблица имя → `f64` | **г/моль** | пять записей, см. ниже | ADR-025, ADR-064 | `reaction_unbalanced_by_element_is_rejected`, `substance_lighter_than_its_declared_composition_is_rejected`, `composition_key_absent_from_conserved_is_rejected` |

`seed` ключом сценария **не является** (ADR-058). Сид приходит параметром запуска
(`--seed`), доходит до генератора четвёртым счётчиком `run_key`, в `config_hash`
не входит — иначе тройка `(seed, config_hash, world_format_version)` вырождается
и развёртка по сиду теряет общую идентичность (§11). Строка `seed` в файле —
ошибка загрузки, и это решение, а не совпадение с `deny_unknown_fields`:
`seed_in_the_scenario_file_is_rejected`. **Расхождение с замороженной спекой:**
SPEC §12.4 говорит «seed в конфиге»; спека не правится (ADR-032), операционная
форма живёт здесь и в `ACCEPTANCE.md`.

`conserved` стоит последней строкой таблицы не по алфавиту и не по важности.
С ADR-064 это таблица, а `config.rs` требует, чтобы скаляры стояли впереди
таблиц: голый ключ после заголовка таблицы в TOML не записать, и каноническая
форма (§11 п. 3) печатает поля в порядке объявления. Схема, поставившая
`conserved` между `dt` и `beta`, выглядела бы исправной и не грузилась бы вовсе.
Тип карты — `BTreeMap`, и это тоже не вкус: при `IndexMap` порядок ключей файла
попадает в канонические байты и краснеет
`whitespace_and_key_order_do_not_change_the_hash`, при `HashMap` хеш перестаёт
быть детерминированным между запусками и краснеет
`same_seed_and_config_give_byte_identical_state` — через прогон, а не через
компилятор.

Умолчание `conserved` — пять записей `C`, `N`, `P`, `S`, `Fe` с их молярными
массами в г/моль, с семью значащими цифрами (требование ADR-043 к `molar_mass`
распространено ADR-064 на эту таблицу: при `Fe = 55.85` сумма для `FE2`
превышает объявленные `55.84500` на 0.005 г/моль, при `Fe = 56` — на 0.155, то
есть реестр проекта отвергается собственной проверкой). ADR-064 печатает три
числа из пяти — `C = 12.01070`, `N = 14.00670`, `Fe = 55.84500`; `P = 30.97376`
и `S = 32.06500` восстанавливаются из его же сверки
`P₄S₃ = 220.09004 = 4·30.97376 + 3·32.06500`, но самой умолчательной таблицы не
печатает ни один документ — **TODO**, §13 п. 23. Пять чисел выписаны здесь как
вывод, а не как объявленное умолчание, и до подтверждения таковыми и остаются.

Двух строк, стоявших здесь прежде, больше нет, и это стоит объяснить, потому что
их отсутствие — результат, а не упущение.

Допуск массового баланса ключом не стал вовсе: он **выводится** как `10⁻⁶` от
массы оборота, а валидатор дополнительно требует, чтобы выведенный допуск был
меньше наименьшей молярной массы среди веществ с пустым составом (ADR-043).
Развилка «корневой ключ или свойство вещества» разрешилась третьим ответом —
ни то ни другое.

Опорное состояние оказалось двумя разными состояниями, и потому не давалось
одним ключом (ADR-044). Термохимическое — 298.15 К — живёт в
`enthalpy_formation` каждого вещества и служит сверке объявленной энтальпии
реакции. Состояние хранения — произвольный сценарный ноль — это `T_ref` в
таблице выше, и оно существует, чтобы не тратить разрядность на постоянную
составляющую.

`T_ref` при этом перестал быть свободным числом. С ADR-062 поле энтальпии
объявляет диапазон температур, и область определения смыкается:
`t_min ≤ T_ref ≤ t_max`. Положение `T_ref` внутри диапазона стоит ровно один бит
`k_E` — в середине диапазона `H_max` вдвое меньше, чем на краю, — поэтому бит
дешёвый, но названный.

> **Пометки `TODO(A-10)` и `TODO(A-11)` ниже по документу устарели.** Оба вопроса
> закрыты записями ADR-043 и ADR-044; ответы — здесь и в §5. Таблицы ключей
> исправлены, прозаические пометки в разборах — ещё нет.

`dt` и `grid.dx` — единственные два числа во всём конфиге, которым позволено
знать про воксель (SPEC §10). Всё остальное выражается в концентрациях, долях и
удельных величинах, а масштабы выводятся (§9).

`conserved` — не косметика. Смена набора меняет множество законных реакций, то
есть динамику, поэтому она входит в `config_hash` и двигает
`WORLD_FORMAT_VERSION` (ADR-025). Имена в таблице произвольны: ADR-025 специально
не перечисляет их в коде, чтобы заряд ложился тем же механизмом
(`charge = 0.0` в `conserved`, `charge = -2` в `composition`) без правки формата.
Отсюда «сохраняемые величины», а не «элементы».

Масса рядом с именем появилась не ради полноты. Третья проверка ADR-033 —
«объявленная масса не меньше суммы масс отслеживаемых величин» — была
неисполнима с того дня, как записана: массу имени валидатору неоткуда взять, а
таблица атомных масс в Rust перечислила бы имена, которых ADR-025 сознательно не
перечисляет. С ADR-064 проверка читается прямо из сценария:
`molar_mass[i] ≥ (1 − ε)·Σ_e composition[i][e]·conserved[e]` по именам с
ненулевой массой, при `ε = 10⁻⁶` из ADR-043. Неравенство **нестрогое**: у `FE2`
запас ровно нулевой (55.84500 против `1·55.84500`), и строгое сравнение
отвергло бы вещество собственного реестра. Нулевая масса — не отговорка, а
несущая деталь: любая ненулевая масса заряда сделала бы то же самое.

`beta` — доля типичного пула, которую позволено съесть одному кванту экстента.
При `2⁻⁶` у реакции не меньше 64 различимых ступеней экстента поперёк пула её
дефицитного реагента, и шум стохастического округления ограничен той же долей.
Уменьшать не бесплатно: `e_r` растёт, а с ней требования к `kᵢ`, и система
неравенств ADR-039 становится несовместной. Увеличивать тоже: химия квантуется
грубее, медленные реакции превращаются в редкие скачки.

## 3. `[grid]`

| Ключ | Тип | Единица | Обязателен / умолчание | Откуда | Стережёт |
|---|---|---|---|---|---|
| `nx`, `ny`, `nz` | `u32` | — | `64` | `config.rs`, QUANTITIES §1 | — (§10, «правила без имени теста») |
| `dx` | `f64` | м | `1.0e-4` | `config.rs`, ADR-013 | `scale_underflow_is_rejected`, `courant_violation_is_rejected` |

Единица размеров сетки — прочерк, как в реестре, а не «вокселей». Иначе
`config_schema_declares_no_voxel_dependent_units` падает на первой же строке
таблицы, и падает справедливо: тест смотрит на схему, а не на смысл.

Рабочее окно `dx` — от `1e-6` до `1e-3` м (ADR-002): снизу режим микро, сверху
допущение об идеально перемешанном вокселе, время перемешивания `dx²/6D`
перестаёт быть много меньше времени реакции. Диапазон `nx…nz` — 32 … 256
(QUANTITIES §1); верх упирается в потолок плотного массива, 3.7 ГБ при 256³.

Ни один из сорока отказов размеры сетки не стережёт.
`substance_count_over_s_max_is_rejected` к ним отношения не имеет:
`S_MAX = 32` выводится из фиксированного размера локальных массивов ядра и из
`width_mask: u32` (ADR-041), а не из бюджета памяти. Отсюда же второе
неохраняемое правило — делимость. `coarse_idx = fine_idx >> lod` есть сдвиг, и
точен он только при размерах, кратных `2^lod` по каждой оси (SPEC §1.5). При
`nx = 50` и `lod = 2` накрывающая ячейка неполна, накопление вверх теряет
вокселы, и расходится та половина ledger, за которую отвечает огрублённое поле.
Оба правила — §10.

Умолчание `64`, а не `128`: SPEC §1.1 считает бюджет памяти на 128³, а загрузчик
ставит 64³ — размер песочницы из ADR-021. Расхождения тут нет, но при чтении
SPEC §1.5 стоит помнить, что `lod` относителен к этой сетке, а не абсолютен
(§7).

## 4. `[boundary]`

| Ключ | Тип | Обязателен / умолчание | Откуда |
|---|---|---|---|
| `x_min`, `x_max` | `periodic` \| `closed` \| `exchange` | `periodic` | SPEC §1.6 |
| `y_min`, `y_max` | то же | `periodic` | SPEC §1.6 |
| `z_min` | то же | `closed` | SPEC §1.6 |
| `z_max` | то же | `exchange` | SPEC §1.6 |

Шесть граней, а не три оси, — **выбор схемы**, и он вынужден: SPEC §1.6 называет
условие независимым по оси, но тут же даёт умолчание, в котором у Z два разных
конца. Периодичность при этом свойство оси, а не грани, поэтому валидатор
требует, чтобы обе грани оси были `periodic` одновременно.

`closed` на `z_min` — твёрдое дно, геотермальный вход, субстрат для биоплёнок.
Полностью периодический 3-тор физически корректен на этом масштабе (броуновское
движение сильнее седиментации) и доступен как опция.

Грань `exchange` работает через канал `BOUNDARY_EXCHANGE` (SPEC §7) и обязана
попадать в счётчик: тест `boundary_outflow_appears_in_channel_counter`. Состав
внешнего резервуара и скорость обмена объявляются секцией ниже (ADR-059).

**Эта грань и есть сток энергии S0, и она же предусловие освещённого
сценария** (ADR-084). Энтальпия — самостоятельное диффузионное поле (ADR-028,
ADR-030), через `exchange` она идёт своим ходом, и весь путь построен:
`DiffusePhase::apply_enthalpy` зачисляет её в `BOUNDARY_EXCHANGE` на каждом
подшаге шагов `c` и `d`, ghost-ячейка несёт энтальпию резервуара при `t_out`, а
`exchange_face_carries_enthalpy_into_the_energy_counter` проверяет это в обе
стороны. `RADIATIVE_OUT` остаётся напечатанным в SPEC §7 и ненаписанным — это
дыра, а не противоречие, и стоком он не является. Отсюда два отказа §10:
`i_surface > 0` требует хотя бы одной грани `exchange` вместе с её секцией
`[boundary.reservoir]`, а сама `i_surface` не может превышать того, что грань
уносит в стационаре (§9). Отсюда же нижняя граница температуры, полученная даром:
двусторонний канал не может охладить домен ниже `t_out`, а `t_out` уже обязан
лежать в `[t_min, t_max]`.

### `[boundary.reservoir]`

| Ключ | Тип | Единица | Обязателен / умолчание | Откуда | Стережёт |
|---|---|---|---|---|---|
| `conc_out` | таблица `id` вещества → `f64` | моль/м³ | обязателен; обязана называть **каждое** вещество реестра | ADR-059 | `reservoir_missing_a_substance_is_rejected`, `reservoir_concentration_above_max_conc_is_rejected` |
| `t_out` | `f64` | К | обязателен; обязан лежать в `[t_min, t_max]` поля энтальпии | ADR-059, ADR-062 | `exchange_face_carries_enthalpy_into_the_energy_counter`; сам диапазон — правило без имени теста (§10) |
| `k_ex` | `f64` | м/с | обязателен | ADR-059 | `exchange_velocity_above_the_courant_limit_is_rejected` |

Секция обязательна тогда и только тогда, когда хоть одна грань объявлена
`exchange`, — а `exchange` есть умолчание на `z_max`, значит почти всегда.
Взаимная обязательность стережётся с обеих сторон:
`exchange_face_without_a_reservoir_is_rejected`. Стоять секция обязана **после**
шести скалярных ключей граней — требование канонической формы, §11 п. 3.

**Каждое вещество реестра обязано быть выписано, и это не педантизм.**
Умолчание «ноль» есть бесконечный сток, а такое утверждение о физике должно быть
напечатано, а не унаследовано. Наследовать концентрации резервуара от начальных
концентраций домена ADR-059 отверг прямо: сила самого крупного внешнего
воздействия оказалась бы остатком начального условия, граница была бы невидима
на старте и тихо становилась бы источником или стоком по мере ухода мира от
начального состояния. Цена названа честно — сценарий прирастает строкой на
вещество.

**Резервуар объявляет температуру, а не только состав.** Энтальпия —
самостоятельное диффузионное поле (ADR-028, ADR-030) и через грань `exchange`
идёт своим ходом, поэтому ghost-ячейка нужна и ей: `t_out` пересчитывается при
загрузке в энтальпию через `T_ref` и `Σ nᵢ·c_p,ᵢ` состава резервуара (ADR-044).
Без этого верх мира оказался бы термически запечатан умолчанием.

**`t_out` обязан лежать в объявленном диапазоне температур.** ADR-059 называет
это одной из пяти проверок резервуара, а имени теста ей не даёт, поэтому правило
стоит среди областей определения §10. Цена нарушения не в педантизме: диапазон
`t_min … t_max` (ADR-062) — это то, из чего выведены `k_E` и разрядность поля
энтальпии (§9), и `t_out` за его границей даёт ghost-ячейку с энтальпией вне
выведенного окна, то есть переполнение поля на первом же обмене вместо отказа
загрузки.

**Скорость обмена одна на резервуар.** Физически она масштабируется как
`D^{1/2}…D^{2/3}`, и одно число на все вещества — объявленное упрощение
(ADR-059); повеществное масштабирование ушло в `OPEN_QUESTIONS.md`. Ключ
калибруемый (ADR-038). Условие устойчивости того же семейства, что
`n = ⌈6·D·dt/dx²⌉`, и проверяется при загрузке: при `dx = 100 мкм` и `dt = 1 с`
предел `k_ex ≤ 10⁻⁴ м/с`, а поршневая скорость кислорода на поверхности моря
около `10⁻⁵ м/с` — запас в десять раз.

**И с ADR-084 это число работает за двоих — честная цена того решения, а не
недосмотр.** Тем же `k_ex` задана тепловая проводимость крышки
`k_ex·Σ(conc_out·c_p)`, Вт/(м²·К) (§9), против которой судится стационар
освещённого сценария. Это разная физика, и совпадение порядков
(`41.71 Вт/(м²·К)` на поставляемом сценарии) не спроектировано, а случайно.
Практическое следствие: калибровка подачи кислорода двигает заодно границу
законных освещённых сценариев. Разведение двух скоростей — вопрос **A-26**
`OPEN_QUESTIONS.md`, а не второй ключ, заведённый без оператора.

Резервуар не истощается: конечное «снаружи» было бы состоянием, а
`Δ(поля + клетки)` из ADR-003 получило бы третье слагаемое, не являющееся ни
полем, ни клеткой (ADR-059). Если конечное «снаружи» когда-нибудь понадобится,
это воксель, а не граничное условие.

## 4а. `[physics]`

Номер с буквой по образцу §7а: секция стоит в файле между `[boundary]` и
`[[substance]]`, а перенумеровать §5 … §13 нельзя — на них ссылается append-only
журнал.

| Ключ | Тип | Единица | Обязателен / умолчание | Откуда | Стережёт |
|---|---|---|---|---|---|
| `g` | `f64` | м/с² | `9.80665` | ADR-085 | `the_medium_constants_have_one_source`, `an_omitted_physics_section_hashes_as_earth_and_fresh_water` |
| `rho_medium` | `f64` | кг/м³ | `1000.0` | ADR-085, ADR-067 | те же |
| `mu` | `f64` | Па·с | обязателен при **включённом процессе оседания**, умолчания нет | ADR-085, ADR-067, SPEC §3 | `a_scenario_that_enables_settling_without_a_viscosity_is_rejected` |

Три ключа, два умолчания, и асимметрия измерена, а не выбрана. По объявленному
диапазону температур в 50 К вязкость воды меняется в **3.27 раза**
(1.79·10⁻³ → 0.547·10⁻³ Па·с), плотность — на **1.18 %**, а `g` не меняется ни
на что; значит защитимое умолчание есть у двух и нет у третьего.

**`9.80665`, а не `9.81`,** и выбор сделан по происхождению числа, а не по его
следствию: `g_n` — точно определённая величина (CGPM, 1901), у которой есть
издание, `9.81` — округление без источника. Разница `0.034 %` целиком съедается
калибровкой скорости осадконакопления, то есть попадает ровно в класс, о котором
ADR-055 говорит «величина без источника годами компенсируется калибровкой», —
поэтому решать по следствию нельзя.

**`1000.0` выведено из собственного реестра проекта.** Поставляемый сценарий даёт
`typical_conc(WATER) = 55500 моль/м³` при `molar_mass = 18.01528 г/моль`, откуда
`999.848 кг/м³`, и `partial_molar_volume = 1.807·10⁻⁵ м³/моль`, откуда `996.97`.
Умолчание стоит на 0.015 % выше первого и на 0.30 % выше второго — обе разницы
внутри температурной полосы. `1025` (морская вода) отвергнуто: раствор в этой
модели уже представлен веществами с объявленным `partial_molar_volume`, и лишние
25 кг/м³ либо считаются дважды, либо суть соль, которой не объявило ни одно
`[[substance]]`.

**Ноль у `g` и у `rho_medium` не запрещён**, и это осознанно: `g = 0` есть
законный сценарий без оседания, а запрет был бы утверждением о физике, которого
запись не делает (тот же ход, что у `partial_molar_volume = 0` в ADR-067 и у
`i_surface = 0` в ADR-076). Цена названа: отличить опечатку от решения тогда
нечем, кроме чтения файла.

**Предикат `mu` — «включён процесс оседания», а не «есть вещество с
`settling_radius > 0`»,** и его диктует код, а не вкус. `SettlePhase::fold`
строит `Settle::new` для **каждой** полосы, чтобы дурное объявление отвергалось
при загрузке, а не игнорировалось за соседство с нулём, а `settling_velocity`
проверяет `mu` **до** ветки нулевого радиуса. Значит фаза, построенная хоть раз,
требует годной `mu` независимо от радиусов, и условие по радиусу неисполнимо в
той форме, в какой его печатал §7 до ADR-085.

**Обе величины — объявленные константы среды, а не величины состояния вокселя**
(ADR-067, подтверждено ADR-085). Повоксельная `Σmᵢ/V_occ` есть частное, у
знаменателя которого нет нижней границы — `V̄` бывает отрицательной, — то есть у
величины полюс; вдобавок `w` перестала бы быть известной при загрузке, а вместе с
ней исчезла бы возможность доказать условие Куранта там. Размер лжи посчитан:
0.85 % в водной толще и в 2.5 раза в уложенном осадке, и второе ADR-067 уже
отдал уплотнению в геологии (SPEC §4.8).

Секция, а не три корневых скаляра: скаляры обязаны стоять впереди таблиц
(§11 п. 3), корень несёт четыре, а `mu` — калибруемый ключ, которому среди них
места нет; в итоге три входа одной формулы снова оказались бы в двух местах.
Все три адресуемы из `[[calibration]]` путём (§8, ADR-038), включая `physics.g`:
запретить это стоило бы списка некалибруемых путей, которого не держит ни одна
запись.

Отсутствующая секция и пустая секция — **одна конфигурация**: `[physics]`
материализуется умолчаниями до хеширования (§11 п. 2, ADR-065), поэтому
каноническая форма сценария, не написавшего ни строки, печатает обе величины.
`mu` при этом не печатается вовсе, пока её не объявили, — по образцу `theta_max`:
материализованное `Some(_)` было бы умолчанием, которого решение не назначало.

## 5. `[[substance]]`

| Ключ | Тип | Единица | Обязателен / умолчание | Откуда | Стережёт |
|---|---|---|---|---|---|
| `id` | строка | — | обязателен | SPEC §2.3 | — |
| `composition` | таблица имя → знаковое целое (`i32`) | атомов на формульную единицу | `{}` (**выбор схемы**) | ADR-025, ADR-064 | `reaction_unbalanced_by_element_is_rejected`, `composition_key_absent_from_conserved_is_rejected`, `negative_composition_entry_with_nonzero_molar_mass_is_rejected` |
| `molar_mass` | `f64` | **г/моль** | обязателен | ADR-033, ADR-043, QUANTITIES §2 | `substance_without_molar_mass_is_rejected`, `reaction_unbalanced_by_mass_is_rejected`, `substance_lighter_than_its_declared_composition_is_rejected` |
| `typical_conc` | `f64` | моль/м³ | обязателен | ADR-039 | `substance_dynamic_range_over_2e14_is_rejected`, `reaction_with_unrepresentable_concentration_spread_is_rejected` |
| `max_conc` | `f64` | моль/м³ | обязателен | ADR-039 | `scale_overflow_is_rejected`, `substance_dynamic_range_over_2e14_is_rejected` |
| `partial_molar_volume` | `f64` | м³/моль | обязателен | ADR-067, SPEC §3 | `substance_without_partial_molar_volume_is_rejected`, `settling_substance_with_zero_partial_molar_volume_is_rejected` |
| `settling_radius` | `f64` | м | обязателен | ADR-067, SPEC §4.5 | `substance_without_settling_radius_is_rejected` |
| `diffusivity` | `f64` | м²/с | обязателен (**выбор схемы**) | SPEC §1.7, QUANTITIES §2 | `every_n_ticks_on_diffusive_field_is_rejected` |
| `c_p` | `f64` | Дж/(моль·К) | обязателен; постоянная | ADR-044, QUANTITIES §5 | `temperature_from_enthalpy_round_trips` |
| `enthalpy_formation` | `f64` | Дж/моль при 298.15 К | обязателен | ADR-044 | `reaction_enthalpy_disagreeing_with_formation_enthalpies_is_rejected` |

**`molar_mass` объявляется, а не выводится.** ADR-025 в следствиях утверждал
обратное, и ADR-033 отменил ровно это следствие: при наборе
`conserved = C, N, P, S, Fe` у воды, кислорода и протона состав пуст, а
выведенная масса вышла бы нулевой — и нулевая масса воды валит массовый баланс
сама. Попутно закрылась дыра: реакция, создающая воду из ничего, элементной
проверкой не ловится в принципе. Второй довод ADR-033 — «`V_occ` без массы не
считается вовсе» — с ADR-067 неверен: `V_occ` складывает объёмы и массы не
знает. Ключ от этого обязательным быть не перестал, но держится теперь на
массовом балансе и на `ρ̄ᵢ` оседающего вещества, а не на вместимости вокселя.

**Единица — граммы на моль**, как во всей таблице SPEC §2.3 и в числах ADR-043
(§13 п. 14). Множитель `10⁻³` живёт ровно в одном месте корпуса —
в `ρ̄ᵢ = molar_massᵢ·10⁻³/V̄ᵢ` (§9), — и другой единицы эта формула не
допускает.

`composition` пуста у веществ без отслеживаемых величин — вода, кислород, протон
(SPEC §2.3). Их баланс держится только массовой проверкой, и это осознанная цена
отказа от отслеживания H и O; третья проверка ADR-033 их тоже не прикрывает —
у пустого состава правая часть неравенства нулевая.

**Значения `composition` знаковые.** Беззнаковый `u16`, объявленный
`QUANTITIES.md` §2, не вмещал обещанного ADR-025 `charge = -2`, то есть механизм,
ради которого имена оставлены произвольными, не работал даже в типе (ADR-064).
Знак при этом не бесплатен: отрицательное значение у величины с **ненулевой**
массой — ошибка загрузки, иначе знак работает как скидка и `C = -1` покупает
право объявить массу на 12.01 г/моль меньше настоящей.

Каждый ключ `composition` обязан разрешаться в `conserved` (ADR-064). Прежде
`Fee = 20` вместо `Fe = 20` было именем, которое просто не проверяют; теперь это
имя, которому нечего сопоставить, и оно отказ загрузки, а не тихий ноль.

Умолчание `{}` при этом — **выбор схемы**, и цена его в том, что забытая секция
неотличима от честно пустой. ADR-025 говорит «каждое вещество объявляет свой
состав», то есть читается как обязательность; умолчание делает объявление
необязательным, и вещество, у которого `composition` забыли, проходит элементный
баланс тождественно, `0 = 0`, а ловится только массовой проверкой — допуск
которой не назван (A-10). Альтернатива — потребовать ключ и писать пустую
таблицу явно; тогда забывчивость становится ошибкой загрузки, а не тихим нулём.

**Обязательность `partial_molar_volume` выбором схемы быть перестала.**
Прежняя строка `density` держалась на прочтении SPEC §3 и была помечена здесь
как выбор схемы честно: источник говорил, что величина есть, и не говорил, что
ключ обязателен. С ADR-067 `V_occ = Σ (amountᵢ/units_per_molᵢ)·V̄ᵢ`, то есть
объём каждого вещества входит в вместимость вокселя прямым слагаемым, и без него
не считается ни давление, ни вытеснение. Обязательность следует из формулы, а не
из выбора. `settling_radius` обязателен по другой причине и тоже не по вкусу:
умолчание «не оседает» сделало бы забытый ключ неотличимым от честного нуля —
`MINERAL` без радиуса дал бы мир, где осадок не оседает никогда, при полностью
зелёном корпусе (ADR-067). `r = 0` при этом не магическое значение: `k = 2·0²/9`
есть точный ноль, и хост просто не заводит процесс для вещества с нулевой `w`.

**«Обязателен» у `diffusivity` — по-прежнему выбор схемы, а не источник.**
SPEC §1.7 говорит, что величина есть и откуда берётся, а не что ключ обязателен;
обязательность выведена здесь из того, что `n` подшагов считается по `D`
каждого. Цена названа честно: для `MINERAL` в SPEC §1.7 `D` нет, то есть при
буквальном чтении не грузится ни один сценарий S0. Сузить обязательность («`D` —
только диффундирующим») значит решить, что именно диффундирует, а такого решения
нет.

**Знак `partial_molar_volume` несущий, и ноль законен.** Ион упорядочивает воду
вокруг себя плотнее, чем она уложена сама, и раствор при его добавлении
сжимается: у `PO₄³⁻` табличное `V̄ ≈ −4.0·10⁻⁵ м³/моль`, у `Fe²⁺ ≈ −2.4·10⁻⁵`,
у `H⁺` — **точно ноль** на общепринятой шкале однойонных объёмов (ADR-067).
Поэтому безусловного `partial_molar_volume ≠ 0` в области определения нет и быть
не может: оно отвергло бы протон, то есть собственный реестр проекта. Запрет
нуля переехал туда, где деление действительно происходит, и записан условным:
`≠ 0` требуется у вещества с `settling_radius > 0`, потому что `ρ̄ᵢ` выводится
делением на `V̄ᵢ` (§9, §10).

`typical_conc` и `max_conc` — физические числа, от `dx` не зависящие. Из них
выводится всё остальное: масштаб вещества, экспонента экстента реакции,
коэффициенты хранения и разрядность (§9). Отношение `max_conc/typical_conc`
ограничено сверху `2¹⁴` — это и есть нижняя граница разрешения, записанная как
неравенство над объявленными числами.

**`max_conc` — не только вход вывода масштаба, но и жёсткий потолок прогона.**
`ξ_max` считается только по входам реакции; потолок выхода держит валидатор через
`max_conc`, и продукт, перешедший объявленный предел, означает неверное
объявление, а не насыщение: прогон обязан упасть громко — ассертом в debug, на
границе тика вместе с ledger в release (ADR-041). Значит `max_conc = 1.0e-2` у
протона в примере §12 объявляет не «где-то около pH 5», а «pH ниже 5 — это ошибка
сценария». Число выбирается с этим пониманием, иначе первый же локальный выброс
останавливает прогон.

Единица энтальпии образования — `TODO(A-11)`, а не «Дж/моль». Строки для неё в
реестре величин нет (§13), ADR-028 называет величину и не называет единицу, а
A-11 держит развилку шире: `c_p` объявляется на моль или на килограмм, и
энтальпия образования пойдёт за ним. Правдоподобное значение в колонке рядом с
`TODO` в соседней колонке переживёт решение как молчаливое умолчание.

Веществ не больше `S_MAX = 32` (ADR-041), и один индекс из этих тридцати двух
занят энтальпией: она участник вектора `ν` наравне с веществом. Значит веществ не
больше тридцати одного. Конкретный номер энергетического индекса ни одним ADR не
задан и приходит с хоста параметром — не полагайся на его значение. Граница честная цена запрета аллокаций в ядре: локальный вектор
спроса `[S_MAX]` обязан иметь фиксированный размер. «Реестр — данные» после этого
означает «данные в пределах объявленной границы», и так и надо говорить.

## 6. `[[reaction]]` и `[reaction.rate]`

| Ключ | Тип | Единица | Обязателен / умолчание | Откуда | Стережёт |
|---|---|---|---|---|---|
| `id` | строка | — | обязателен | ADR-027, ADR-090 | `reaction_id_is_stable_under_reordering_in_toml`, `two_reaction_names_folding_to_one_id_are_rejected`, `a_reaction_id_landing_in_a_reserved_purpose_window_is_rejected` |
| `inputs` | таблица `id` вещества → целое > 0 | — | обязателен | SPEC §5, QUANTITIES §6 | `reaction_stoichiometry_must_be_positive_integers` |
| `outputs` | то же | то же | обязателен | SPEC §5, QUANTITIES §6 | то же |
| `enthalpy` | `f64` | **Дж/оборот** | обязателен | ADR-028, QUANTITIES §6 | `reaction_unbalanced_by_energy_is_rejected`, `reaction_energy_delta_is_integral_after_load` |
| `energy_from` | строка: имя канала \| `""` | — | `""` | SPEC §5, ADR-028, ADR-059 | `reaction_unbalanced_by_energy_is_rejected`, `channel_name_outside_the_enumeration_is_rejected`, `energy_from_light_is_rejected` |
| `catalyst` | `guild:<id>` \| `expr:<k>` \| `""` | — | `""` (абиотическая) | SPEC §5 | — |
| `requires` | массив `{ field, min, max }` | по полю | `[]`, и **непустое значение незаконно** до появления ворот (ADR-073) | SPEC §5, ADR-073 | `a_requires_window_is_rejected_until_the_gate_exists` |
| `rate.vmax` | `f64` | оборотов/(с·м³) при `catalyst = ""`, иначе оборотов/(с·моль катализатора) | обязателен | ADR-047, ADR-063 | `abiotic_reaction_proceeds_with_empty_catalyst`, `catalyzed_rate_equals_abiotic_rate_times_catalyst_concentration` |
| `rate.km` | таблица `id` → `f64` | моль/м³ | обязателен по каждому входу | SPEC §5 | — |
| `rate.t_vmax` | `f64` | К | обязателен, умолчания нет | ADR-048, QUANTITIES §6 | `reaction_without_t_vmax_is_rejected` |
| `rate.q10` | `f64` | — | обязателен | SPEC §5 | — |

**Стехиометрия молярна и цела по определению.** Уравнять химическое уравнение и
значит найти целые коэффициенты (ADR-026); дробный коэффициент — не приближение,
а ошибка. Ноль и отрицательное значение — тоже: сторону выбирает секция, а не
знак.

Единица при этом прочерк, как в реестре (`s[i]`, QUANTITIES §6), а не «моль на
оборот»: коэффициент безразмерен, размерность появляется только при умножении на
`ξ`. Тип в реестре `i32`, а в конфиге «целое > 0», и противоречия здесь нет:
знак придаёт секция при разрешении в вектор `ν`, поэтому в §12 та же величина
печатается как `sᵢ = −1, −2`. В TOML знака нет нигде.

**`vmax` измеряется в оборотах, и оборот — не моль.** Для реакции с составом
Редфилда один оборот это 106 моль углерода. Переписать стехиометрию, не тронув
`vmax`, значит сдвинуть скорость на два порядка молча. `km` этим не задета: она в
концентрациях субстрата и от размера оборота не зависит.

**Единица `vmax` условна по значению соседнего ключа `catalyst`** (ADR-063).
При `catalyst = ""` это обороты в секунду на кубометр и множителя катализатора в
кинетике нет вовсе; при непустом — обороты в секунду на моль катализатора, и
множителем входит его концентрация. Обе ветви сходятся по размерности на `rate`,
ниже которой `x = rate·dt·V_voxel·2^e_r` их не различает: ни `xi`, ни `ν`, ни
округление о катализаторе не знают. Новых отказов из этого не следует, и это
надо сказать вслух — обе формы законны, `vmax = 0.08` при пустом катализаторе и
то же число при `catalyst = "guild:M_PHOTO"` суть два правильных конфига.

Цена развилки — дисциплина, и её негде проверить. Дискриминант не стоит рядом с
тем, чем управляет: `catalyst` живёт в `[[reaction]]`, `vmax` — в
`[reaction.rate]`, поэтому дописывание `catalyst = "guild:X"` к готовой реакции
молча меняет единицу ключа в другой таблице, а копирование `vmax` между
реакциями разных типов по-прежнему выглядит как копирование числа. Оба состояния
законны, отказать тут не на чем. Разбирается `[reaction.rate]` при этом не в
отрыве от родителя: таблицы TOML не упорядочены, единицу `vmax` в момент чтения
ключа знать нельзя, и развилка переезжает в проверку после разбора всей записи
`[[reaction]]`.

**Энтальпия — участник реакции наравне с веществом** (ADR-041). Она входит в
вектор `ν` отдельной записью, иначе её приращение округлялось бы независимо от
вещественного и энергетическая половина инварианта расходилась бы тем же
механизмом, каким расходился килограммовый учёт до ADR-026. Цена названа честно:
объявленная `enthalpy` вещественна, поэтому `ν_E = ΔH · 2^(k_E − e_r)` целым не
выходит и округляется **при загрузке**, один раз, а валидатор обязан сообщить
наведённую относительную ошибку числом.

**Область значений `energy_from` замкнута** (ADR-059): это имена перечисления
каналов — `SOLAR_IN`, `GEOTHERMAL_IN`, `RADIATIVE_OUT`, `BOUNDARY_EXCHANGE`,
`IMPACT`, `VENT_BURST` — либо пустая строка. Реестр каналов живёт в коде и
сценарием не расширяется: канал есть правая сторона равенства, которым
проверяется всё остальное, и реестр, редактируемый сценарием, позволил бы
закрыть любую невязку объявлением седьмого канала. Практическая граница
проходит так: **канал — код, его модуляция — данные.**

Пустая строка означает «из энтальпии своего вокселя»: это внутренний перенос,
обе половины инварианта сохраняются, а от ухода энтальпии в минус реакцию
удерживает `ξ_max` — энтальпия участник вектора `ν` наравне с веществом
(ADR-041). Непустое значение означает «списано со счётчика канала» и законно
**только** для реакции, чья энтальпия не сходится против `Σ νᵢ·ΔH_f,ᵢ`, — а
ADR-044 такую реакцию не грузит. В S0 законна поэтому только пустая строка:
непустая ветвь существует как форма валидатора, а не как рабочий путь.

**`energy_from = "LIGHT"` незаконно**, хотя SPEC §5 печатает его в примере
фотосинтеза. Причина учётная, а не формальная: ADR-049 зачисляет убыль
интенсивности в энтальпию шагом `i′`, поэтому к моменту шага `h` световая
энергия уже внутри учёта, и списание её через канал вычло бы её второй раз —
энергетическая невязка вышла бы ненулевой ровно на фотосинтетический поток.
Правильное написание — `energy_from = ""`. Спека заморожена (ADR-032);
операционная форма расхождения — `energy_from_light_is_rejected`.

**Порядок реакций в файле не значит ничего, и это защищено дважды.**
`reaction_id` берётся от имени, а не от позиции (ADR-027): иначе перестановка
двух строк меняет поток случайных чисел стохастического округления и, значит,
прогон. Сворачивает имя `numeric::name_key` — `mix(START)`, затем по одному
раунду того же смесителя на каждый байт UTF-8 имени, как оно написано в TOML,
без `trim`, без приведения регистра и без нормализации Unicode (ADR-090); любое
из трёх сдвинуло бы каждый бросок реакции во всех прогонах, прошлых и будущих.
Отдельно — применение: все реакции вокселя считают спрос по одному
снимку состояния, конкурируют общим коэффициентом и применяются один раз
(ADR-041). Тесты разные и ловят разное:
`reaction_id_is_stable_under_reordering_in_toml` и
`reaction_result_is_independent_of_order_in_toml`.

Реакций не больше `R_MAX = 64` (ADR-041), по той же причине, что и веществ.

## 7. Поля и процессы

Разрешение задаётся на поле, включение и частота — на процесс. Это не одно и то
же, и SPEC §1.5 разделяет их специально.

### `[[field]]`

| Ключ | Тип | Единица | Обязателен / умолчание | Откуда |
|---|---|---|---|---|
| `id` | строка | — | обязателен | SPEC §1.5 |
| `lod` | `u8`, 0 … 2 | — | `0` (**выбор схемы**) | SPEC §1.5, QUANTITIES §1 |
| `thermal_diffusivity` | `f64` | м²/с | обязателен при `id = "enthalpy"` | ADR-062 |
| `t_min` | `f64` | К | обязателен при `id = "enthalpy"` | ADR-062 |
| `t_max` | `f64` | К | обязателен при `id = "enthalpy"` | ADR-062 |

Поля из SPEC §1.5: количества веществ, гильдии и признаки, скорость среды,
энтальпия, геология, свет. Идентификаторы — **выбор схемы**.

`lod` относителен к `[grid]`: `coarse_idx = fine_idx >> lod`. SPEC §1.5 называет
для энтальпии 32³, подразумевая базовую сетку 128³; на 64³ та же `lod = 2` даёт
16³.

Огрубление сетки — единственный законный способ удешевить быстрое поле. Число
подшагов диффузии падает квадратично с шагом: переход со 128³ на 32³ делит его на
шестнадцать, и энтальпия из безнадёжной становится шестью подшагами.

**Умолчание `lod = 0` — выбор схемы, и цена его молчалива.** SPEC §1.5 задаёт
умолчания не числами `lod`, а сетками: скорость среды 64³, энтальпия и геология
32³. Перенести их в схему механически нельзя — `lod` относителен к `[grid]`, а
таблица SPEC написана от базовых 128³, — но и нуль не следует ни из чего.
Сценарий, забывший запись `[[field]] id = "enthalpy"`, получает энтальпию на
мелкой сетке, где подшагов ровно в `2^(2·lod)` раз больше — в шестнадцать при
`lod = 2`, то есть **84** вместо названных ADR-030 шести. Восемьдесят четыре, а
не 96: `⌈16·5.25⌉`, а не `16·⌈5.25⌉` — шестнадцать умножается на 5.25 **до**
потолка, а не после (ADR-062). Стоит это 896 проходов по ячейке против шести,
то есть больше, чем весь перенос вещества вместе взятый. Останавливает это
`N_MAX = 64` (ADR-061): поле, которому по его `D`, `dt` и `dx` нужно больше
подшагов, отвергается при загрузке —
`field_over_n_max_substeps_is_rejected`, — а сообщение обязано назвать поле,
его `n` и вычисленный `Δlod = ⌈log₄(n/64)⌉`, то есть тот выход, который здесь
работает. Ключа конфига, поднимающего границу, нет и не будет: он не способен
изменить ни одного результата, только превратить отказ в прогон. `N_MAX` живёт
в `crates/liminis-core/src/process/diffuse.rs` рядом со `STABILITY_LIMIT` —
граница сборки того же рода, что `S_MAX` и `R_MAX`, но по другому основанию:
те существуют потому, что ядру запрещены аллокации, эта — потому, что бюджета
тика в конфиге нет.

**Поле энтальпии объявляет свою температуропроводность и свой диапазон
температур** (ADR-062). `n = ⌈6·D·dt/dx²⌉` считается на поле, а `diffusivity`
объявлено на вещество (§5) — энтальпия же не вещество, и без собственного ключа
шесть подшагов ADR-030 были цитатой, а не вычислением. Теперь считаются: при
`dx = 100 мкм`, `lod = 2` (грубый шаг `4·10⁻⁴` м), `dt = 1 с` и
`thermal_diffusivity = 1.4·10⁻⁷ м²/с` выходит `6·D·dt/dx² = 5.25`, `n = 6`,
`alpha = 0.1458` против предела `1/6`. Валидатор сверяет `α` с самым быстрым
объявленным `diffusivity` — `1.4·10⁻⁷` против `9.3·10⁻⁹` у протона,
пятнадцатикратный запас, — и утверждение ADR-028 «тепловая диффузия быстрее
всего в системе» становится проверкой
(`thermal_diffusivity_below_the_fastest_substance_is_rejected`).
`every_n_ticks_on_diffusive_field_is_rejected` впервые получает энтальпию как
случай.

`t_min` и `t_max` объявляются в кельвинах, а не в джоулях, и это не
единообразие ради единообразия: джоули на ячейку — число, знающее про воксель,
а смена `dx` или `lod` меняла бы `V_cell` в `2^(3·lod)` раз и обесценивала бы
объявленный диапазон молча (SPEC §10, §9). Из диапазона выводится рабочий
размах энтальпии, из него — `k_E`, `units_per_joule` и разрядность поля (§9);
`T_ref` обязан лежать внутри (§2).

### `[[process]]`

| Ключ | Тип | Обязателен / умолчание | Откуда | Стережёт |
|---|---|---|---|---|
| `id` | строка | обязателен | SPEC §8 | — |
| `enabled` | `bool` | **умолчание объявляет сам процесс** | ADR-065, SPEC §4.1, ADR-018 | тесты «alone», `an_omitted_process_section_hashes_as_the_full_default_roster` |
| `every_n_ticks` | `u32` | `1` | SPEC §1.7, ADR-030 | `every_n_ticks_on_diffusive_field_is_rejected` |

`reads`, `writes` и `invariant` из таблицы SPEC §4.1 ключами конфига **не
являются**: они свойства реализации, а не сценария, и объявляются в коде
оркестрации (ADR-034). Расхождение декларации с фактическим доступом там
перестаёт быть невидимым. Стоящий в том же листинге `lod` ключом процесса не
является по другой причине: разрешение — свойство поля, а не процесса, и
объявляется в `[[field]]` (SPEC §1.5). Сказать это надо вслух, иначе автор
валидатора добавит `lod` процессу по SPEC §4.1 и получит отказ от
`deny_unknown_fields` без объяснения.

**Отсутствие записи `[[process]]` означает умолчание процесса, а не его
отсутствие** (ADR-065). Перечень процессов замкнут и живёт в коде под
`process/`; каждый процесс объявляет собственное умолчание `enabled` рядом со
своим инвариантом, а загрузчик материализует полный перечень **до** хеширования.
Отсюда три следствия, и каждое стоит назвать.

Первое: пользователь, забывший запись про диффузию, получает работающую
диффузию, и его `config_hash` побайтово совпадает с хешем коллеги, эту запись
выписавшего (§11 п. 2). Предупреждения он не видит и не должен — ничего
неверного не случилось. В канонической форме при этом стоит строка, которой он
не писал, и каноническая форма растёт примерно в девять раз: девять записей
S0 по ~65 байт поверх ~70 байт нынешнего `hello.toml`.

Второе, ловушка, и она ровно одна: **удаление записи больше не выключает
процесс.** Тот, кто стёр блок света, чтобы света не было, получит свет.
Единственный способ выключить — написать `enabled = false`. Пришедший с моделью
плагинного реестра получит противоположное задуманному, молча и без ошибки, — и
поэтому это сказано здесь, а не выведено читателем из §11.

Третье: умолчание живёт под `process/`, а не в схеме, и это не вкусовщина. CI
роняет PR, трогающий `configs/**`, `kernels/**` или `process/**` без инкремента
`WORLD_FORMAT_VERSION` (ADR-020, ADR-036), а правку `config.rs` не ловит — §11
называет эту слепую зону прямо. Реестр в схеме позволил бы перевернуть умолчание
с `true` на `false` и сменить семантику каждого прогона, не уронив ничего. По
той же причине умолчание не может быть одним на всю схему: `enabled = true`
включило бы поле скоростей, у которого `u_conv_max` обязателен и умолчания не
имеет, и `configs/scenarios/hello.toml` перестал бы грузиться, а зеркальное
`false` сделало бы `hello` пустым миром, выглядящим исправным конфигом.

`deny_unknown_fields` здесь не работает: serde видит поля структуры и не видит
значений, а `id` — значение. Неизвестное имя процесса и дубль имени ловятся
ссылочной целостностью (§10): `an_unknown_process_id_is_rejected` и
`a_duplicate_process_id_is_rejected`. Второй не про аккуратность — молчаливое
«побеждает последний» сделало бы каноническую форму зависящей от порядка записей
в файле.

**Порядок процессов конфигом не задаётся.** Он записан в SPEC §8, входит в
семантику мира и его перестановка двигает `WORLD_FORMAT_VERSION` (ADR-036,
ADR-020) — хотя ни один конфиг и ни одно ядро при этом не менялись. Ключа
`order` в схеме нет и быть не должно.

**`every_n_ticks > 1` для диффузионного поля запрещён.** Пропуск тиков умножает
эффективный `dt`, то есть делает ровно то, что запрещает условие устойчивости
(ADR-030). Редко обновляется только то, что диффузией не является: геология
(`3600` по SPEC §4.8) и внешние события. Имя ключа взято из SPEC §1.7 и §8;
контракт плагина в SPEC §4.1 называет то же поле `every_n` — §13.

Параметры отдельных процессов. Группировка — **выбор схемы**; решениями
зафиксированы только сами величины и их единицы, а обязательность — лишь там,
где в колонке нет пометки.

|---|---|---|---|---|
| свет | `k_w`, `k_b`, `k_d`, `k_m` | 1/м | обязательности не назначало ни одно решение — **выбор схемы**, §13 п. 23 | SPEC §4.6, QUANTITIES §5 |
| свет | `i_surface` | Вт/м² | обязателен при включённом процессе, умолчания нет — по прецеденту `u_conv_max`. **Средняя за период модуляции**, не мгновенная | ADR-076, SPEC §4.6 |
| свет | `daily_fraction` | — (доля `i_surface`) | `0` | ADR-076 |

| свет | `seasonal_fraction` | — (доля `i_surface`) | `0` | ADR-076 |
| свет | `seasonal_period` | с | обязателен при `seasonal_fraction > 0`; те же два правила | ADR-076 |

**Колонка обязательности заполнена не везде, и пустоты названы, а не закрыты
догадкой.** Обязательности, назначенные решением, — `u_conv_max` и условный
`stir_period` (ADR-069), с ADR-076 `i_surface` и условная пара периодов
модуляции, с ADR-082 `theta_max`. У четвёрки `k_w … k_m` её по-прежнему не
назначал никто, и поставить сюда «обязателен» значило бы завести отказ загрузки,
которого не требует ни один ADR: с ADR-065 запись `[[process]]` можно не писать
вовсе, а умолчания `enabled` пяти процессов из девяти не назначены ничем
(§13 п. 23), поэтому неизвестно даже, при каком условии эти ключи вообще
читаются.

Констант среды в этой таблице больше нет: `mu` переехала отсюда в `[physics]`
вместе с `g` и `rho_medium` (ADR-085, §4а), и предикат её обязательности сменился
с «есть вещество с `settling_radius > 0`» на «включён процесс оседания» — по
доводу из кода, выписанному в §4а. Переезд `mu` в этот документ был вынужденным
дважды: сперва из параметров давления (ADR-067), потому что при
`pressure.enabled = false` оседанию вязкость брать было неоткуда, затем из
`[[process]]` вовсе, потому что запись процесса можно выключить, а среду нельзя.
Собственного ключа `k` у оседания нет и не будет: коэффициент выводится из
радиуса частицы, `k = 2r²/9` (§9), а значение `2.2·10⁻¹¹ м²` не имеет читаемого
прообраза — неверное такое число неотличимо от верного и компенсируется
калибровкой скорости осадконакопления вечно.

**Верхняя оценка модуля скорости больше не отсутствует, а выводится** (ADR-069).
Она нужна не процессу, а валидатору: условие Куранта и условие на исходящий
поток проверяются при загрузке по консервативной оценке (SPEC §4.2). Поле
скоростей предписанное — ротор хранимого потенциала, — и подвижность `L` не
объявляется, а выводится из `u_conv_max` и объявленного диапазона `t_min … t_max`
так, что `|u_конв| ≤ u_conv_max` точно, а общая оценка есть
`(1 + stir_fraction)·u_conv_max` (§9). Рантайм-нормировки, то есть глобальной
редукции посреди тика, при этом не требуется вовсе. Оба отказа §10 получают
вход — первый, но не единственный: `w_sed` оседания даёт им второй,
независимый, и складывать их в одно неравенство нельзя (§10).

`α_T` и `ρ₀` ключами не становятся (ADR-069): в схему их привела бы стоксова
`L`, которую ADR-069 отверг арифметикой — выведенная из первых принципов оценка
превышает потолок `dx/(6·dt)` примерно в тысячу раз, и вывод существует, но
всегда даёт отказ загрузки.

**`g` ключом стало, и это отменённое следствие, а не оговорка документа.**
ADR-085 отменяет следствие ADR-069 в части `g`; само решение ADR-069 и исключение
`α_T` и `ρ₀` остаются в силе. Разница между ними и была разницей по существу:
`α_T` и `ρ₀` после отказа от стоксовой `L` не входят никуда, а `g` осталось
входом живого вывода — `w_sed,ᵢ = k_sed·(ρ̄ᵢ − ρ_среды)·g/μ` считается при
загрузке (§9, ADR-067, SPEC §4.5) и служит вторым, независимым входом отказов по
Куранту и по исходящему потоку. Второй довод, стоявший здесь, — «калибровать
ускорение свободного падения незачем» — снят отдельно: он верен как утверждение о
том, чего разумный автор хотеть не станет, и ложен как утверждение о том, что
схема запрещает (§4а, §8).

**Буква `k` в этом документе занята тремя разными величинами:** выведенной
экспонентой масштаба `k[i]` (§9), её энергетическим двойником `k_E` (§9) и
четвёркой `k_w … k_m` в свете. Коэффициент оседания из этого списка ушёл — он
выводится и в TOML не попадает (ADR-067); жёсткость давления ушла тоже, и не в
вывод, а вовсе: ADR-082 отменил её как величину, потому что при выводе
подвижности она сокращается вместе с `dt` и `dx` и неверная жёсткость не меняет
ни одного бита прогона. Первые две — не ключи; из оставшихся имя есть только у
света, и разводить больше нечего.

**Жёсткость объявить нельзя — с одной оговоркой, без которой утверждение
ложно.** Поля `k` в `config/schema.rs::Process` нет и не появится, а
`deny_unknown_fields` отвергает неизвестный ключ. Но та же плоская структура
**принимает** `k_w … k_m` на любой записи процесса, включая давление, поэтому
запрет держится на выборе буквы, а не на форме схемы, — и приёмочного имени на
этом строить не стоит (ADR-082).

## 7а. `[initial]`

Номер с буквой, а не «8»: секция стоит в файле между `[[process]]` и
`[[calibration]]`, а перенумеровать §8 … §13 нельзя — на них ссылается
append-only журнал, и правка сделала бы эти ссылки ложными.

| Ключ | Тип | Обязателен / умолчание | Откуда | Стережёт |
|---|---|---|---|---|
| `layer.<вещество>` | `sediment` \| `water` \| `uniform` | умолчание `sediment`, материализуется на все вещества | ADR-077 | `initial_layer_side_outside_the_enumeration_is_rejected`, `initial_layer_naming_an_unknown_substance_is_rejected` |

Один ключ, и это выбор записи, а не незаконченность. Из четырёх величин, из
которых `worldgen/` собирает начальное состояние, свойством **сценария**
является ровно одна: какие вещества обогащены в осадке, а какие в водной толще.
Полоса `excursion = min(typical, max − typical)/2` ратифицирована выводом, а не
ключом; показатель спектра октав и база счётчика `purpose` остаются границами
сборки с открытым вопросом (A-17). Обоснования всех трёх отказов — в ADR-077.

**Таблица «имя → значение», как `composition` и `conc_out`.** `deny_unknown_fields`
её ключей не видит (§11 п. 1), поэтому `O_2 = "water"` при объявленном `O2` —
отказ ссылочной целостности, стадия 1 (§10), а не serde. Значение вне
перечисления ловит serde, и тест закрепляет это как решение, а не как совпадение.

**Умолчание печатается, а не подразумевается.** Загрузчик дополняет таблицу
записью на каждое объявленное вещество до хеширования (ADR-065, ADR-077):
сценарий, не написавший ни строки, и сценарий, выписавший `sediment` пятью
строками, — одна конфигурация и один `config_hash` (§11 п. 2). Цена — строка на
вещество в канонической форме и то, что переименование вещества двигает секцию.

Умолчание `sediment` — физическое утверждение, которого не писал ни один
сценарий: «каждое вещество обогащено в осадке». Оно даёт вертикальный градиент
без единого химического фронта, и взамен даёт устойчивую стратификацию на
нулевом тике, без которой `density_stratification_persists_without_forcing` не
имеет начального условия. Перекрывается одной строкой.

`uniform` значит «слоевого члена нет», а не «поле вышло константой»: вещество,
объявленное `uniform`, несёт собственный шум полной амплитуды и константой не
является. Одноимённый флаг `uniform` в отчёте загрузки `worldgen/` — про другое,
про вырождение поля, и это единственная тревога отчёта.

**Расхождение с SPEC §12.4, три места** (ADR-032: спека не правится, расхождение
записывается). §12.4 называет три слоя — осадок, вода, воздух, — а перечисление
знает две стороны и «однородно»: воздуха в мире нет ни полем, ни границей.
§12.4 обещает «всё параметризуемо», а секция параметризует одну величину и языка
генераторов не заводит. И §12.4 требует симплекс-шума, тогда как `worldgen/`
реализует решётчатый value noise со smoothstep-затуханием; от шума требуются
свойства, а не имя алгоритма (`ACCEPTANCE.md`).

## 8. `[[calibration]]`

| Ключ | Тип | Обязателен / умолчание | Откуда | Стережёт |
|---|---|---|---|---|
| `path` | строка | обязателен | ADR-038 | `calibration_path_that_leads_nowhere_is_rejected` |
| `min`, `max` | `f64` | обязательны | ADR-038 | — |
| `scale` | `linear` \| `log` | обязателен, умолчания ADR-038 не называет | ADR-038 | — |

Порядок записей в списке **и есть** порядок координат вектора поиска. Он живёт в
конфиге, а не выводится из порядка полей структуры: иначе рефакторинг схемы молча
менял бы размерность и порядок координат, то есть обесценивал бы предыдущие
поиски.

Синтаксис пути — **выбор схемы**: точечный, с адресацией массивов по `id`, а не
по индексу (`reaction.h2s_oxidation.rate.vmax`). Адресация по позиции повторила
бы ошибку, от которой ADR-027 избавлялся в `reaction_id`.

Логарифмическая шкала объявляется на параметр, потому что скорости реакций
охватывают порядки, и поиск в линейной шкале тратит почти все пробы на верхнюю
декаду.

**Границы наследуют условную единицу `vmax`.** При
`path = "reaction.<id>.rate.vmax"` числа `min` и `max` заданы в той единице,
которую назначает соседний ключ `catalyst` (§6, ADR-063), а
`calibration_path_that_leads_nowhere_is_rejected` проверяет разрешимость пути, не
единицу. Новой проверки на это нет, и вывести её не из чего.

**Секция указывает на ключ путём и не подменяет его.** Числа, которого нет в
`config_hash`, в модели быть не может: два прогона, различающиеся только
значением внутри `[[calibration]]`, получили бы одинаковый хеш, и тройка
`(seed, config_hash, world_format_version)` перестала бы быть идентичностью
прогона. Поэтому `l_c` — обычный ключ процесса поля скоростей (§7), а секция
лишь адресует его; ADR-069 отверг обратное прямо. Границы поиска для него —
от `L_домена/8` до `L_домена/2`, и нижняя не косметическая: при ячейках
короче четверти домена перенос идёт как `Pe^{1/2}` и порог «на порядок сильнее
диффузии» из `ACCEPTANCE.md` не берётся. Калибруемы по ADR-038 и `k_ex` (§4), и
`physics.mu` (§4а) — обычные ключи, у которых есть путь. С ADR-085 к ним
прибавились `physics.g` и `physics.rho_medium`: адресуемость следует из того, что
ключ есть, и запись разрешает её молчанием, а сказать это надо вслух — запрет
потребовал бы списка некалибруемых путей, которого не держит ни одна запись.

Секция **не входит в `config_hash`** (§11) и проверяется при загрузке: путь,
никуда не ведущий, — ошибка, а не пустая координата.

## 9. Что в конфиге не появляется, потому что выводится

SPEC §10 требует, чтобы ни один параметр конфига не имел вокселя в единицах.
Вывод — механизм, которым это требование соблюдается, а не дисциплина, которой
его соблюдают. Смена `dx` пересчитывает масштабы сама; в конфиге не остаётся
числа, знающего про воксель, кроме `dx` и `dt`.

Ни один ключ, пришедший с ADR-056 … ADR-069, этого не нарушает, и проверить это
можно по единицам: `V̄` в м³/моль, `settling_radius` в метрах,
`thermal_diffusivity` в м²/с, `t_min` и `t_max` в кельвинах, `u_conv_max` и
`k_ex` в м/с, `l_c` в метрах, `conc_out` в моль/м³. `config_schema_declares_no_voxel_dependent_units`
остаётся зелёным. Оговорка одна и общая: половинный `dx` удваивает число Куранта
оседания и адвекции, поэтому сценарий, грузившийся при 100 мкм, при 50 мкм может
быть отвергнут — это свойство условия устойчивости, а не единицы ключа.

| Величина | Из чего выводится | Решение |
|---|---|---|
| `V_voxel` | `dx³` | SPEC §1.1 |
| `units_per_mol[i]`, `k[i]` | `kᵢ = max( ⌊log₂( 2³¹/8 / (max_conc,ᵢ · V_voxel) )⌋, max e_r по реакциям с участием i )` | ADR-039, ADR-040 |
| `e_r` реакции | `⌈max по участникам log₂( sᵢ / (β · typ_conc,ᵢ · V_voxel) )⌉` | ADR-039 |
| `ν[i]` | `sᵢ · 2^(kᵢ − e_r)` | ADR-039 |
| `w_s` | `round( enthalpy_formation,s · 2^(k_E − k_s) )` — химическая энергия одной единицы хранения вещества; вес левой части энергетического инварианта | ADR-081 |
| `ν_E` | `−Σ_s ν_s·w_s`, суммируется при загрузке и **сразу в направлении поля**: у экзотермической записи положительна. Объявленная `enthalpy` — то, с чем эта сумма сверяется, а не то, из чего она считается | ADR-081, отменяет формулу ADR-041 |

| `n` подшагов диффузии | `⌈6·D·dt/dx²⌉` на поле, с учётом его `lod`; для энтальпии `D` — это `thermal_diffusivity`; не больше `N_MAX = 64` | ADR-030, ADR-062, ADR-061 |
| `reaction_id` | от имени реакции, не от позиции в файле | ADR-027 |
| масштаб полей признаков `BT` | типичная биомасса × типичное значение признака | ADR-039 |
| `V_occ` | `Σ (amountᵢ/units_per_molᵢ)·V̄ᵢ` — сумма объёмов, без массы и без множителя `10⁻³` | ADR-067 |
| `ρ̄ᵢ` | `molar_massᵢ·10⁻³/V̄ᵢ`, кг/м³; единственный оставшийся переход моль→килограмм | ADR-067 |
| `k_sed,ᵢ` | `2r²/9`, м², из `settling_radius`; через диаметр то же есть `d²/18` | ADR-067 |
| `w_sed,ᵢ` | `k_sed·(ρ̄ᵢ − ρ_среды)·g/μ`, м/с; известна при загрузке точно, а не оценкой. Все три константы среды — ключи `[physics]` (§4а, ADR-085); выводится сама `w_sed`, и выводит её `process/settle.rs`, а валидатор зовёт её, а не повторяет вторым текстом | ADR-067, ADR-085, SPEC §4.5 |

Шесть последних групп строк — `alpha_ex` и `a_out`, `ρ̄`, `k_sed` и `w`, а также
трафик паритета — ни одна запись журнала не называет адресно; они внесены сюда
по контракту самого раздела: величина, выведенная при загрузке из объявленного,
обязана здесь стоять, иначе автор валидатора выведет её сам и по-другому.

**Две строки отчёта про свет печатаются раздельно, и это решение, а не
вёрстка** (ADR-076). Множитель модуляции имеет единичное среднее по построению,
поэтому объявленный диапазон проходится за одно и то же число тиков при любой
модуляции; деление срока на пик даёт отношение мгновенных скоростей в единицах
времени и в отчёте читается как консервативная оценка. Пик при этом
специфицируется против `A_N·max_n max(0, sin)`, а **не** против `π`: при `N = 4`
— законном по собственному правилу «не меньше трёх тиков» — выборки суть
`0, 1, 0, 0`, `A_4 = 4`, и пик равен ровно 4.0, то есть на 27 % выше `π`.
**Строка отчёта про давление печатает четыре числа, а не одно, и это тоже
решение** (ADR-082). Запас устойчивости без предела, с которым он сравнивается,
нечитаем: `α = 8·10⁻⁴` одинаково хорошо читается как «мало» и как «много», —
поэтому в строке стоит и `α`, и предел `1/6`. Оба входа окна печатаются рядом,
потому что на поставляемом реестре `Θ_sup` и `Θ_typ` отличаются на 0.2 % и
перепутать их местами не заметит ни один тест, а на реестре с широким
динамическим диапазоном (ADR-039 разрешает до 2¹⁴) окно от такой перестановки
инвертируется. Отдельно: `Q` сегодня `f32`, а весь сигнал давления на
поставляемом реестре живёт в 0.5 % над единицей, поэтому большинство граней
округлится в ноль — строка отчёта единственное место, где это может стать
видимым.

**Строка отчёта про крышку печатает запас в битах, а не тик переполнения, и это
довод, а не формат** (ADR-084). После ADR-083 счётчик `i128`, и тика
переполнения у крышки нет ни при каком объявленном мире: `1.4·10¹⁸` единиц за
тик против `2¹²⁷` дают `1.2·10²⁰` тиков, а весь интеграл затухающего переходника
упирается в семьдесят бит. Строка, печатающая «тик переполнения», печатала бы
число, которого не бывает. Печатается это **вместо отказа**, и тоже решением:
отказ миру, у которого `t_out ≠ T_ref` при работающей крышке, накрыл бы
единственный запускающийся сегодня сценарий и почти любой вентилирующий мир —
то есть был бы ответом на вопрос о разрядности запретом вопроса. Рядом с
зачислением печатается энтальпия ghost-ячейки: без неё граница неаудируема без
второго прогона, а с ней множитель между ними — `alpha_ex` на число грубых ячеек
— проверяется на бумаге.

Минимальная `τ` на мелкий воксель — третья строка, которую ADR-076 называет, и
её сегодня печатать не из чего: аттенюатор есть `k` на безразмерную меру
хранения, а какая это мера, не решено ни одним документом
(`TODO(attenuation-measure)`), и `k_w … k_m` ни в какую таблицу не доезжают.

**`k_E` выводится системой, а не назначается** (ADR-062). Диапазон:
`H_max = C_cell · max(t_max − T_ref, T_ref − t_min)`, где
`C_cell = Σᵢ typical_conc,ᵢ · V_cell · c_p,ᵢ` — теплоёмкость **грубой** ячейки
поля энтальпии.

```
k_E ≥ max по реакциям ⌈ e_r + log₂( (0.5/ε) / |ΔH_r| ) ⌉      значимость ν_E
k_E ≤ min по реакциям ( e_r + ⌊log₂( (2³¹−1) / |ΔH_r| )⌋ )    ν_E помещается в i32
k_E ≤ ⌊log₂( 2^(w−4) / H_max )⌋                               поле не переполняется
```

Третье неравенство — формула ADR-039 `2³¹/8`, обобщённая на разрядность `w`;
`ε = 10⁻⁶` не выбирается заново, это допуск ADR-043, взятый затем, чтобы
энергетическая сторона не была грубее массовой. Нижнюю границу задаёт реакция с
самой мелкой энергией кванта, а не с самой большой энтальпией, — точный двойник
правила «квант задаёт самый дефицитный участник». Для реестра SPEC §2.3 окно при
`i32` пусто, при `i64` — `[61, 67]`, и берётся верх: точность бесплатна, когда
разрядность уже оплачена. Самый дешёвый ответ — оставить `k_E` на потолке `i32`,
то есть 35, — даёт `ν_E = 0.0126` у окисления сульфида, то есть ноль после
округления: реакция идёт, тепла не выделяет, а энергетический ledger сходится,
потому что один и тот же ноль стоит по обе стороны. Отсюда отдельный отказ
`energy_scale_incompatible_with_a_reaction_enthalpy_is_rejected`.

**`typical_conc` получает вторую работу, и это цена.** Она вводилась ради `e_r`
(ADR-039); теперь через `C_cell` она же задаёт масштаб энергии, то есть небрежно
объявленная типичная концентрация двигает `ν_E`, а не только квант экстента.

Две строки этой системы легко переставить местами, и цена перестановки высока.
**Масштаб вещества определяется его потолком**, чтобы поле не переполнилось при
максимальной концентрации. **Квант экстента определяется самым дефицитным
участником реакции**, а не самым обильным: лимитирует тот, кого мало. Привязка
кванта к `k_min` делает `ν` дефицитных участников больше, чем весь их пул, и
реакция не совершается ни разу — молча, без единой падающей проверки. Тест
`extent_exponent_is_derived_from_the_scarcest_participant` стоит именно здесь.

**Подъём `kᵢ` до `e_r` стоит в самой формуле, а не в примечании к ней.** Потолок
переполнения задаёт `kᵢ` сверху, целочисленность `νᵢ` — снизу: `kᵢ ≥ e_r` для
каждой реакции, где вещество участвует. Обе половины решаются совместно
(ADR-039), поэтому выбирается большее из двух, и только так получается число,
которое ADR-040 называет для воды. Плоская формула потолка даёт воде `k ≈ 52` при
`e_r = 63` — то есть `kᵢ < e_r` и нецелое `ν`, чего в решённой системе не бывает.
Автор валидатора копирует таблицу, а не прозу под ней, поэтому подъём записан в
строке.

Запас над потолком — три двоичных порядка: формула оставляет при `max_conc`
около `2²⁸` единиц против `2³¹−1`. `kᵢ`, поднятая до `e_r` больше чем на три,
в `i32` не помещается — отсюда `i64` и отсюда же
`storage_width_is_derived_not_declared`. В реестре SPEC §2.3 такое вещество ровно
одно, вода: при `e_r = 63`, который задаёт протон в одной с ней реакции, она
держит `5.1·10¹¹` единиц. Правило при этом общее, а не про воду.

**`molar_mass` в этот список не входит: она объявляется** (ADR-033). Это ровно то
место, где ADR-025 был отменён в части следствия, и перепутать легко: всё
соседнее по смыслу выводится, а она — нет.

## 10. Семьдесят четыре отказа против правил схемы

Три строки пришли с ADR-082 и все три про давление: отсутствие обязательного
`theta_max`, пол окна `6·Θ_sup` и потолок по объявленному горизонту прогона.
Четвёртой строки — `every_n_ticks` на давлении — здесь нет намеренно: правило
§10 сформулировано по **полю**, а не по оператору, поэтому у
`every_n_ticks_on_diffusive_field_is_rejected` расширилась область, а не завелось
имя-двойник.

С ADR-085 повторилось то же движение и ровно с тем же счётом: ушёл
`a_settling_substance_is_refused_until_g_and_the_medium_density_are_named` —
временный отказ, снятый вместе со своим правилом, потому что `g` и плотность
среды теперь объявлены (§4а), — а на его место встали два узких: зерно при
выключенном оседании и включённое оседание без вязкости. Число в заголовке снова
пересчитано по строкам таблицы.

Ещё одна ушла и две пришли с ADR-084 (вместе с ADR-083), и это минус один плюс
два, а не переформулировка. `a_lit_scenario_is_refused_until_an_energy_sink_exists`
был двухзамковым: разрядность счётчика сняла ADR-083, отсутствие стока — ADR-084,
объявив стоком S0 уже построенную грань `exchange` (§4). Замков не осталось,
поэтому строка **удалена вместе со своим правилом**, а на её место встали два
узких отказа освещённому сценарию. Число в заголовке пересчитано по фактическим
строкам таблицы, а не сложением дельт.

Две строки пришли с ADR-090 и обе про `reaction_id`. Стоят они сразу за
`a_duplicate_id_in_any_section_is_refused` по роду сравнения — тот сверяет имена
на равенство, эти две сверяют свёртку имени с чужой свёрткой и с объявленным
окном; ADR-090 позиции не назначает, и выбор здесь именно выбор. Заодно
пересчётом поймано расхождение в `ACCEPTANCE.md`: над семьюдесятью именами там
стояло слово «шестьдесят девять», а фраза про эту таблицу называла семьдесят
одну строку при фактических семидесяти двух. Инвариант «§10 на две больше» всё
это время держался — врал счёт, а не таблица.

Имена — дословно из `ACCEPTANCE.md`, порядок тот же. Число получено пересчётом
строк этой таблицы, а не сложением дельт из записей журнала: каждая из
ADR-056 … ADR-069 берёт базой одно и то же число девятнадцать, и сложить их
заявленные абсолюты значит получить мусор. Заголовок §10 при этом врал с тех
пор, как ADR-043, ADR-044 и ADR-048 добавили строки, — и никто не заметил, что
над восемнадцатью строками стоит слово «шестнадцать». Проверяется счёт
пересчётом обоих документов, а не доверием к заголовку.

Два отказа из тех трёх, что пришли из ADR-039, называют не вещество, а **пару
«вещество, реакция»** — `reaction_with_unrepresentable_concentration_spread_is_rejected`
и `stoichiometry_in_storage_units_fits_i32`; сообщение обязано назвать обе
стороны, потому что конфиг, в котором виновата пара, нельзя починить, глядя на
одно имя. Третий, `substance_dynamic_range_over_2e14_is_rejected`, сравнивает два
ключа одного вещества и о реакциях не знает: по колонке «Ключи» это видно.
`ACCEPTANCE.md` считает парными все три (§13).

**Отказ по `kᵢ ≥ e_r` наступает позже, чем кажется.** Неравенство — не условие
отказа, а условие целочисленности `ν`, и удовлетворяется оно подъёмом `kᵢ` (§9).
Вещество, которому при поднятой `kᵢ` не хватает `i32`, переезжает в `i64`
(ADR-040); отказ остаётся только на случай, когда не хватает и `i64`. Записанное
безусловно, это правило отвергло бы собственный реестр проекта — вариант,
буквально отвергнутый в ADR-040 («отвергаемым реестром оказывается собственный
реестр проекта»), — и завалило бы
`water_is_stored_in_64_bits_in_the_default_registry`. `ACCEPTANCE.md` формулирует
то же условно: несовместность реестра существует **при `i32` для воды**.
С поправкой строка почти сливается со `scale_overflow_is_rejected`: отказ у обеих
наступает на одном неравенстве, «не помещается и в `i64`». Различает их, откуда
взялась `kᵢ` — у соседки от собственного потолка вещества, здесь от `e_r`
реакции, в которой оно участвует. Разница видна ровно в сообщении: там виновато
вещество, здесь пара.

**Два входа условия Куранта не складываются в одно неравенство.** С этой пачкой
`courant_violation_is_rejected` и `outflow_bound_violation_is_rejected` впервые
получают, что проверять, и получают сразу с двух сторон: `u_conv_max` поля
скоростей (шаг `c` порядка тика, ADR-069) и `w_sed` оседания (шаг `f`,
ADR-067). Прочтение «оба входа — в одно неравенство SPEC §4.2» выглядит
консервативным и потому безопасным, а на деле отвергает законные сценарии и,
хуже, заводит один общий бюджет, который кто-нибудь однажды ослабит. При
расщеплении Ли — Троттера (ADR-036) каждый оператор применяется полным шагом и
обходится **собственным** условием устойчивости; у оседания перенос идёт по
одной оси, исходящая грань одна, и оба неравенства §4.2 для него совпадают.
Смещение за тик складывается из трёх слагаемых — `0.167` вокселя от адвекции,
не более одного от давления, не более одного от оседания, — то есть не более
2.17 вокселя, и это утверждение о модели, а не неустойчивость.

Обязательный предел исходящего потока при `dx = 100 мкм` и `dt = 1 с` есть
`dx/(6·dt) = 16.7 мкм/с`, а не 33: множитель три, который дала бы нулевая
дивергенция, не берётся, потому что дивергенция точна на сетке скорости 64³, а
не на мелких гранях 128³ (ADR-069). Числа корпуса — 100 мкм/с в SPEC §3 и
50 мкм/с в ADR-054 — при `dt = 1 с` не грузятся, и это не ошибка валидатора.

Три строки таблицы правила не имеют или имеют неполное, и это находки, а не
пропуски документа.

- **`reaction_unbalanced_by_mass_is_rejected`.** Допуск не назван (A-10).
  Выбранный наугад он либо пропустит реакцию, создающую воду, либо завалит
  собственный реестр проекта.
- **`reaction_unbalanced_by_energy_is_rejected`.** Требует энтальпии образования
  на вещество, числа для которой в корпусе нет ни у одного вещества (§13 п. 23).
  Ключ и единица решены ADR-044, значения — нет.
- **`scale_underflow_is_rejected`.** Описание в `ACCEPTANCE.md` — «сценарий
  экорежима при микрорежимном `dx` обязан отказаться грузиться, а не считать воду
  одной единицей» — пережило свою причину. После ADR-039 масштаб выводится из
  `max_conc` и `V_voxel` совместно, разрешение при типичной концентрации выходит
  `2²⁸·typ/max` и от `dx` не зависит вовсе. Единица на воксель требует
  `max/typ ≈ 2²⁸`, а это отвергается раньше и строже соседней проверкой на
  `2¹⁴`. Осмысленное правило, которое остаётся за этим именем, — окно `dx`
  из ADR-002.

### Правила, снабжённые именем этой правкой

Три класса проверок ниже имени теста не имели; теперь имеют, и все пятнадцать
имён стоят в таблице выше. Правила при этом не решения: каждое следует из уже
принятого, и без него следствие ломается молча. Раздел оставлен, потому что
таблица называет правило одной строкой, а цена нарушения считается здесь.

**Ссылочная целостность.** `id` вещества, реакции, поля и процесса обязаны быть
уникальны в своей секции (`a_duplicate_id_in_any_section_is_refused`,
`a_duplicate_process_id_is_rejected`); всякое имя, на которое ссылаются — ключи
`inputs` и `outputs` (`a_reaction_naming_an_unknown_substance_is_rejected`),
`rate.km` (`km_missing_for_a_reaction_input_is_rejected` и
`km_naming_a_substance_outside_the_inputs_is_rejected`), форма `catalyst`
(`a_catalyst_outside_the_declared_forms_is_rejected`), ключи `composition`
(`composition_key_absent_from_conserved_is_rejected`) и `conc_out` в обе стороны
(`reservoir_missing_a_substance_is_rejected` и
`a_reservoir_naming_an_unknown_substance_is_rejected`), — обязано
разрешаться в объявленный `id` или в имя из `conserved`. Одно имя из перечня
остаётся без содержания: `field` в `requires` разрешать не во что, и это
записано отдельным пунктом §13. Разрешимость `guild:<id>` внутри `catalyst`
проверяется формой, а не реестром: реестра гильдий в S0 нет, он приходит в S1, и
это граница стадии, а не забытая проверка. Цена нарушения считается точно. Два одинаковых
`reaction.id` дают один `reaction_id` (ADR-027: идентификатор берётся от имени),
то есть один поток случайных чисел на две реакции: стохастическое округление
перестаёт быть независимым, прогоны расходятся, и ни одна проверка не падает.
Опечатка в имени вещества внутри `inputs` даёт либо реакцию, не сходящуюся по
элементам и отвергнутую «не тем» сообщением, либо — если та же опечатка стоит с
обеих сторон — реакцию, сходящуюся тождественно.

Обещание §11 п. 1 этого не покрывает. `deny_unknown_fields` работает по полям
структуры, а `composition`, `inputs`, `outputs` и `rate.km` — таблицы
«имя → значение», где имя данные, а не поле. Опечатка проходит ровно в тех
четырёх ключах, где она вероятнее всего.

**Область определения.** Прочие отказы сравнивают числа между собой и
молчат о том, какие числа вообще законны. Перечень ниже **и есть** критерий
`every_domain_rule_refuses_its_own_violation`: тест табличный, по кейсу на
строку, и краснеет от выпавшей строки — чего два десятка отдельных тестов не
умеют. Рядом стоит `a_not_a_number_never_passes_a_domain_rule`: `nan` ложен во
всяком сравнении, поэтому каждое правило обязано быть записано «отказать, если
не конечно **или** вне диапазона», а не «отказать, если вне диапазона», и
разница видна только на этом кейсе. Строки: `dt > 0`, `dx > 0`, `nx, ny, nz ≥ 1`
и кратны `2^lod`, `typical_conc > 0`, `max_conc > 0`, `typical_conc ≤ max_conc`,
`molar_mass > 0`, `partial_molar_volume` конечен, `settling_radius ≥ 0`,
`conserved[e] ≥ 0`, `beta > 0`, `every_n_ticks ≥ 1`, `km > 0`,
`q10 > 0`, `thermal_diffusivity > 0`, `t_min < t_max`, `k_ex > 0`,
`conc_out,ᵢ ≥ 0`, `t_min ≤ t_out ≤ t_max`, `u_conv_max > 0`, `l_c > 0`,
`stir_fraction ∈ [0, 1]`,
`stir_period > 0` при `stir_fraction > 0`, `physics.g ≥ 0` и конечно,
`physics.rho_medium ≥ 0` и конечно, `physics.mu > 0`,
в `[[calibration]]` — `min < max` и `min > 0` при `scale = "log"`.
Три последние пришли с ADR-085 (§4а) строками перечня, а не отдельными именами.
Ноль у первых двух законен и нарушением не считается; `physics.mu > 0`
проверяется **безусловно**, а не в ветке «при включённом оседании», и это не
педантизм: оседание выключено во всех сценариях репозитория, поэтому условное
правило пропустило бы отрицательную вязкость целиком, а табличный тест этого не
увидел бы — сообщение `settling_velocity` тоже содержит `mu`.
Прежней строки `density > 0` здесь нет, и её отсутствие — решение, а не
пропуск: требуется конечность `partial_molar_volume`, а запрет нуля стоит
условным правилом `partial_molar_volume ≠ 0` при `settling_radius > 0`, у
которого есть собственное имя теста (§10). Безусловный запрет отверг бы протон,
у которого `V̄` на общепринятой шкале равен точно нулю, то есть отверг бы
собственный реестр проекта (ADR-067).
Строка `t_min ≤ t_out ≤ t_max` — пятая проверка резервуара из ADR-059, и она
единственная из пяти, которой запись не дала имени теста; теперь имя есть —
`t_out_outside_the_declared_temperature_range_is_rejected`, — и все пять стоят
в таблице выше. Здесь она не украшение: диапазон температур задаёт `k_E` и
разрядность поля (§9), и `t_out` за его границей переполняет ghost-ячейку
энтальпии вместо того, чтобы отказать при загрузке (§4).

Всё это вынуждено формулами, а не выбрано: `typical_conc = 0` уходит под
логарифм в `e_r` и даёт `inf` или панику раньше любого сообщения; `km = 0` при
нулевом субстрате даёт `0/0` в `S/(K+S)`; `min ≤ 0` при логарифмической шкале
не имеет смысла вовсе. Отдельный случай — `typical_conc > max_conc`: он проходит
все сорок отказов, потому что отношение меньше единицы и, значит, меньше
`2¹⁴`, и даёт масштаб, выведенный от потолка ниже типичного пула.

**Делимость сетки.** `nx, ny, nz` кратны `2^lod` по каждой оси для наибольшего
объявленного `lod` (§3). Имя — `a_grid_not_divisible_by_its_coarsest_lod_is_rejected`,
и слово «наибольшего» в нём несущее: проверенное против наименьшего объявленного
`lod` правило зелено на любом сценарии с одним мелким полем.

Третья проверка ADR-033 из этого раздела ушла: с ADR-064 у неё есть и ключи —
`conserved` как таблица «имя → молярная масса», — и имя,
`substance_lighter_than_its_declared_composition_is_rejected` (§10). Это
единственная проверка проекта, видящая подмену г/моль на кг/моль: массовый
баланс её пропускает, потому что он отношение и тысяча в нём сокращается.

## 11. Что входит в `config_hash`

Прогон идентифицируется тройкой `(seed, config_hash, world_format_version)`
(ADR-016, ADR-020). Чтобы идентичность что-то значила, хеш обязан зависеть от
конфигурации, а не от того, как набран файл. Контракт реализован в
`crates/liminis-core/src/config.rs` и состоит из четырёх свойств.

1. **Типизированная структура с `deny_unknown_fields`.** Опечатка в имени ключа —
   ошибка загрузки, а не молча проигнорированная строка, которая ничего не меняет
   и хешируется так же. Тест `an_unknown_field_is_an_error`. Покрытие у механизма
   уже, чем звучит: он видит поля структуры и не видит ключей таблиц
   «имя → значение» — `composition`, `inputs`, `outputs`, `rate.km`. Там опечатку
   ловит ссылочная целостность (§10), а не serde.
2. **Умолчания применяются до хеширования.** Пропущенный ключ и выписанное
   умолчание — одна конфигурация. Тест `an_omitted_field_hashes_as_its_default`.
3. **Каноническая форма — сериализация отдельного заимствующего типа-проекции
   `Hashed<'a>`, а не всей структуры `Config`** (ADR-066). Проекция собирается
   из `Config` функцией с исчерпывающей деструктуризацией — без `..`, — поэтому
   несимулируемый ключ исключается по построению, а новый ключ схемы **не
   компилируется**, пока про него не принято решение: расхождение ловит
   компилятор, а не глаз. Полей у проекции тринадцать (`name`, `dt`,
   `conserved`, `beta`, `T_ref`, `grid`, `boundary`, `physics`, `substance`,
   `reaction`, `field`, `process`, `initial`) против сорока листовых ключей
   схемы: вложенные
   типы заимствуются целиком, зеркалить надо только путь к исключаемому полю.
   Двенадцатое поле — `[initial]` (ADR-077), тринадцатое — `[physics]`
   (ADR-085), и оба стоят среди таблиц, а не среди скаляров, по требованию этого
   же пункта. **Место поля внутри проекции не стережёт ничто:** перестановка
   компилируется, меняет `config_hash` каждого сценария и не роняет ни одной
   проверки — шапка `config/hash.rs` говорит это прямым текстом. Стороны слоя
   материализуются на все
   вещества **до** хеширования, как и перечень процессов и умолчания `[physics]`,
   поэтому сценарий,
   опустивший секцию, и сценарий, выписавший умолчание, дают один `config_hash`.
   Исключаемое перечисляется константой `NOT_HASHED` — сегодня одна запись,
   `calibration`, — и ключ, вычеркнутый подчёркиванием и не внесённый в список,
   роняет `the_projection_covers_every_simulated_key` с именем пути. Соседний
   `the_canonical_form_reloads_to_the_same_hash` ловит поле, которое
   сериализуется в форму, не читаемую обратно.
   Пробелы, комментарии и порядок ключей в файле не влияют
   (`whitespace_and_key_order_do_not_change_the_hash`), значение — влияет
   (`changing_a_value_changes_the_hash`). Отсюда требование, записанное в
   `config.rs`: скаляры обязаны стоять впереди таблиц, потому что в TOML голый
   ключ после заголовка таблицы не записать. Ровно поэтому `conserved` (§2) и
   `[boundary.reservoir]` (§4) стоят там, где стоят.
4. **`blake3` от канонических байт, первые 16 hex, префикс `blake3:`.**

**Не входит:**

- `[[calibration]]` — ADR-038, тест `config_hash_ignores_the_calibration_section`.
  Секцию читает поисковый драйвер, а не цикл тика, значит повлиять на динамику
  она не может. Отсюда общее правило: **хеш покрывает то, что читает симулятор, и
  ничего сверх.** Проверяется секция при этом всё равно — валидатор ей не
  симулятор. Механизм исключения — проекция из п. 3 (ADR-066).
- `seed` — иначе тройка вырождается: развёртка по сиду давала бы новый
  `config_hash` на каждый сид, и галерея сидов лишилась бы общей идентичности.
  Это следует из ADR-016 и ADR-020; ключом сценария сид при этом не является
  вовсе (§2, ADR-058), а если бы стал, исключение стоило бы одной строки
  `seed: _` в деструктуризации и одной строки в `NOT_HASHED`.
- выведенные величины — `units_per_mol`, `e_r`, `ν`, разрядность, `n` подшагов.
  Они функция объявленного, и хешировать их значит хешировать одно и то же
  дважды.
- `WORLD_FORMAT_VERSION` и версия тулчейна — отдельные координаты идентичности, а
  не часть хеша (ADR-020, ADR-024).

Два следствия действующей реализации стоит назвать вслух, потому что оба
срабатывают беззвучно.

**Хеш не переживает роста схемы.** Проекция локализует **решение о том, что
хешируется**, но не байты: добавление симулируемого ключа с умолчанием меняет
`config_hash` **каждого** существующего сценария, не меняя ни одного из них — и
должно, потому что меняется то, что читает симулятор. Перестановка полей в
Rust-структуре делает то же самое и уже без всякого «должно»: порядок вложенных
ключей живёт в схеме, а не в проекции. Выигрыш от ADR-066 ровно один и ровно
тот, который нужен: добавление **не**симулируемого ключа больше не двигает ни
один хеш. CI ловит правку `configs/**`, `kernels/**` и `process/**` без
инкремента `WORLD_FORMAT_VERSION`, а правку схемы не ловит: там меняется не
семантика мира, а идентичность прогонов — величина, которую ADR-020 не
рассматривает.

**Хеш не переживает и роста реестра процессов, но этот рост сторожится.**
Загрузчик материализует полный перечень процессов до хеширования (§7, ADR-065),
поэтому появление нового процесса в коде сдвигает `config_hash` каждого
существующего сценария, ни одного из них не меняя. Разница с предыдущим абзацем
в том, что реестр живёт под `process/**` и сдвиг приезжает вместе с инкрементом
`WORLD_FORMAT_VERSION`: беззвучным он не бывает. Перестраховка односторонняя —
прогоны объявляются несравнимыми чаще необходимого (выключенный по умолчанию
процесс ничего не делает, состояние побитово прежнее), ложной сравнимости не
возникает никогда. Переход S0 → S1 сдвинет хеши всех сценариев S0 ровно по этой
причине. Строки `id` попадают в хеш через каноническую форму, значит и
переименование процесса в коде — сдвиг идентичности всех сценариев, под тем же
сторожем.

**`conserved` вносит в хеш числа, которых не читает ни один тик**, и правило
«хеш покрывает то, что читает симулятор, и ничего сверх» нарушается здесь
осознанно (ADR-064). Молярные массы разрешаются при загрузке и до тика не
доживают, но живут в том же ключе, что имена, а имена динамику меняют;
исключить часть поля из канонической формы нечем — проекция работает по полям,
не по частям поля. Цена конкретна: правка `C = 12.01070` на `12.011` меняет
`config_hash` прогона, не меняя ни одного тика. Прецедент рядом — `name`
хешируется, не влияя на динамику.

**`name` попадает в хеш.** Он читается симулятором и потому проходит по правилу
ADR-038, хотя на динамику не влияет: два прогона одинаковой физики под разными
именами получат разную идентичность. То же относится к частоте наблюдений, если
она станет ключом.

## 12. Пример сценария

S0-уровень: абиотическое окисление сероводорода, четыре вещества, одна реакция,
ни гильдий, ни клеток. Реакция названа в SPEC §4.7 среди тех, ради которых
абиотическая химия входит в S0 (ADR-031).

Числа веществ — данные сценария, а не решения проекта. Молярные массы взяты из
таблицы SPEC §2.3 и печатаются в **граммах на моль**, как она их и печатает
(§5, §13 п. 14); коэффициенты диффузии — из SPEC §1.7, кроме сульфата: его в
таблице нет, и стоящее здесь число — такая же заготовка под калибровку, как
концентрации. Концентрации — обычные значения водной химии, и они предмет
калибровки тоже; концентрации резервуара — того же рода, и они выписаны, а не
унаследованы от домена, потому что ADR-059 наследование отверг. Всё, чего
**проект** не решил, стоит закомментированным `TODO`: **в этом виде сценарий не
грузится, и это точное отражение состояния проекта**, а не дефект примера.

```toml
name = "h2s-oxidation"
dt = 1.0

# Доля типичного пула на квант экстента, 2⁻⁶ (ADR-039).
beta = 0.015625

# Состояние хранения энтальпии; обязано лежать в [t_min, t_max] поля
# (ADR-044, ADR-062). Здесь совпадает с термохимическими 298.15 К.
T_ref = 298.15

# Ключа seed здесь нет и быть не может: сид — параметр запуска (--seed 42,
# ADR-058), в config_hash не входит, строка в файле есть ошибка загрузки.

# Умолчание, выписанное явно: хеш от этого не меняется (§11). Таблица, поэтому
# стоит после всех скаляров (§2, §11 п. 3). Г/моль, семь значащих цифр
# (ADR-043, ADR-064).
[conserved]
C  = 12.01070
N  = 14.00670
P  = 30.97376              # TODO(§13 п. 23): ADR-064 печатает только C, N и Fe;
S  = 32.06500              # P и S восстановлены из его сверки
Fe = 55.84500              # P₄S₃ = 220.09004 = 4·30.97376 + 3·32.06500

[grid]
nx = 64
ny = 64
nz = 64
dx = 1.0e-4                # 100 мкм, экорежим. V_voxel = 1e-12 м³

[boundary]
# x и y остаются периодическими по умолчанию.
z_min = "closed"
z_max = "exchange"

# Обязательна, потому что грань z_max объявлена exchange (ADR-059). Стоит после
# шести скалярных ключей граней — требование канонической формы (§11 п. 3).
```

### Почему он не грузится

Причин четыре, и все одного рода: ключ назван, единица решена, числа в корпусе
нет. Пятой, `t_vmax`, больше нет — ADR-086 применил правку ADR-048 к §6, ключ
объявлен обязательным и в примере выписан.

Прежних причин было шесть, и закрылись три. ADR-062 закрыл две: поле энтальпии
получило `thermal_diffusivity`, `t_min` и `t_max`, поэтому шесть подшагов теперь
считаются, а не цитируются, — и он же назвал энтальпию окисления сульфида,
`−8.46·10⁵ Дж/оборот`, на месте которой в примере стоял `TODO(A-11)`. ADR-063
закрыл третью, назвав единицу `vmax` условной по `catalyst`. Четвёртая, прежний
`density`, **не закрылась**: ADR-067 говорит это прямо — «обязательный ключ
сменил имя, а не исчез», — и она стоит ниже пунктом 3 под новым именем.

Прибавилась одна: `u_conv_max` — поле скоростей перестало быть неопределённым
(ADR-069) и включилось, а рабочего числа корпус не называет. `t_vmax` прибавлялся
здесь прежде и больше не прибавляется: ключ объявлен (ADR-086). Шесть минус три
плюс одна — четыре.

Была и ещё одна непосчитанная, и она закрылась: `T_ref` обязателен с ADR-044, а
в примере его не было. Теперь он выписан.

Секция `[physics]` в этот список не входит и в примере не выписана вовсе, и это
демонстрация умолчания, а не пропуск (§4а, ADR-085): `g` и `rho_medium` имеют
умолчания и материализуются до хеширования, а `mu` обязательна только при
включённом процессе оседания — которого пример не включает. Оседающего вещества в
примере S0 по-прежнему нет, но причина у этого другая, чем была: не неназванная
плотность среды, а отсутствие рабочего радиуса в корпусе — SPEC §1.3 печатает
**размеры**, а не радиусы, `MINERAL` оседающим стать не может (у него не объявлен
`partial_molar_volume`, ADR-046), и всякое зерно был бы выдумкой.

1. **`c_p` ни у одного вещества.** Ключ и единица решены ADR-044, чисел нет:
   SPEC §2.3 такой колонки не имеет, `QUANTITIES.md` их не печатает.
2. **`enthalpy_formation` ни у одного вещества**, то же самое. Отсюда же
   `reaction_enthalpy_disagreeing_with_formation_enthalpies_is_rejected` не
   может сойтись: объявленная `enthalpy = −8.46·10⁵` сверяется против суммы,
   которую не из чего сложить.
3. **`partial_molar_volume` у `H2S` и `O2`.** ADR-067 печатает четыре значения,
   и эти два в них не входят.
4. **`u_conv_max` при включённом поле скоростей.** Корпус даёт предел
   16.7 мкм/с и прямо говорит, что 50 мкм/с не грузится, а рабочего числа не
   называет.

По этим же причинам не печатаются здесь `k_E` и `units_per_joule`: числа 67 и
`1.476·10²⁰` посчитаны ADR-062 на полном реестре SPEC §2.3, а `C_cell` этого
примера без `c_p` не считается вовсе.

Ещё одной причины, которая была возможна прежде, больше нет. Свет (шаг `a`),
оседание (`f`), фазовые переходы (`g`) и внешние каналы (`j`) записями
`[[process]]` здесь не объявлены, и это законно: перечень процессов замкнут,
отсутствие записи означает умолчание процесса (ADR-065), а не его включение и не
его отсутствие. Прежде развилка «нет записи — нет процесса» против «умолчание
`true` распространяется и на отсутствующую запись» делала неопределёнными и
`k_w … k_m`, и коэффициент оседания; теперь неопределённым остаётся только то,
чему равны сами умолчания, — сегодня не назначено ничем, кроме поля скоростей
(`false`, ADR-069) и оговорки про `advection` там же, §13 п. 23. Геологии в этом
перечне нет и быть не может: в реестре S0 её нет, она приходит в S4 (ADR-065).

### Что проверит валидатор

**Элементный баланс.** По сере: слева `1·1 = 1`, справа `1·1 = 1`. По C, N, P и
Fe обе стороны нулевые. Точное равенство целых.

**Массовый баланс.** `34.1 + 2·32.0 = 98.1` против `96.1 + 2·1.0 = 98.1`.
Сходится точно, поэтому допуск, выведенный по ADR-043, этот пример не задевает.
Обратите внимание, что он сошёлся бы и в килограммах: массовый баланс —
отношение, и множитель в тысячу в нём сокращается. Ловит подмену единицы одна
проверка на весь проект — третья, ADR-033 в записи ADR-064, — и здесь она даёт
`34.1 ≥ 1·32.06500` у `H2S` и `96.1 ≥ 1·32.06500` у `SO4`; в килограммах обе
стороны разошлись бы в четырёхсот раз.

**Заряд.** `0` и `0`: сульфат `−2`, два протона `+2`. Не проверяется — `charge`
не объявлен в `composition` и не входит в умолчательный `conserved`. Объявить
его теперь можно одной строкой `charge = 0.0` в `[conserved]` и знаковыми
значениями в `composition` (ADR-064); нулевая масса при этом обязательна.

**Масштабы.** При `V_voxel = 1e-12` м³ и `β = 2⁻⁶`:

| Вещество | `max_conc` | `kᵢ` | пул при `typical_conc`, ед. | `sᵢ` | `νᵢ` | `β · пул` |
|---|---|---|---|---|---|---|
| `H2S` | 10.0 | 64 | `1.8·10⁶` | −1 | −8 | `2.9·10⁴` |
| `O2` | 1.0 | 67 | `3.7·10⁷` | −2 | −128 | `5.8·10⁵` |
| `SO4` | 100.0 | 61 | `6.5·10⁷` | +1 | +1 | `1.0·10⁶` |
| `H_ION` | 0.01 | 74 | `1.9·10⁶` | +2 | +16384 | `3.0·10⁴` |

`e_r = 61`, и задаёт её протон — самый дефицитный участник, ровно как предписывает
ADR-039. Четыре неравенства проходят: `kᵢ ≥ e_r` (у сульфата с равенством),
`νᵢ ≤ 2³¹−1`, `νᵢ ≤ β·пул` (у протона с наибольшим запасом расхода — квант съедает
чуть больше половины разрешённого), `max_conc/typical_conc ≤ 2¹⁴` (наибольшее
отношение — сто).

**Разрядность.** Количества при `max_conc` укладываются в `1.5 … 2.3·10⁸` единиц
против `2³¹−1`, поэтому все четыре вещества хранятся в `i32`. Добавить в эту же
реакцию воду — и `kᵢ` воды придётся поднять до `e_r`, а она уедет в `i64`
(ADR-040). Пример показывает вывод, а не список имён.

**Подшаги диффузии.** `n = ⌈6·D·dt/dx²⌉`: у `H2S` и `SO4` один, у `O2` два, у
протона шесть, у поля энтальпии шесть на его грубой сетке — `6·1.4·10⁻⁷·1/(4·10⁻⁴)² = 5.25`,
потолок 6, `alpha = 0.1458` против предела `1/6`. Ни одному процессу не разрешён
`every_n_ticks > 1`, и ни одно поле не подходит к `N_MAX = 64`: ближайшее —
энтальпия при забытом `lod`, 84 подшага, и это отказ (§7).

**Паритет полос.** Из четырёх веществ примера чётное число подшагов у двух —
`O2` (2) и `H_ION` (6), — значит меньшинство здесь не определено однозначно, и
восстановительная копия обойдётся в две полосы из четырёх. Число это свойство
конфига, а не кода: порог между `n = 1` и `n = 2` стоит на
`D = dx²/(6·dt) = 1.67·10⁻⁹ м²/с`, и `H2S` с его `1.6·10⁻⁹` сидит в четырёх
процентах под ним — калибровочный сдвиг диффузии переносит полосу через паритет
и меняет счёт копий, не сказав ни слова. Поэтому загрузчик обязан печатать
восстановительный трафик в байтах на тик рядом с числом подшагов (§9, ADR-057).

## 13. Чего в схеме нет

Четыре величины перечислены в `QUANTITIES.md`, раздел «Что не объявлено нигде», и
в схеме им место как ключам с пометкой, а не как значениям: `c_p` на вещество и
опорное состояние энтальпии (A-11), допуск массового баланса (A-10), единицы
давления `P` и жёсткости `k` (A-7). Все четыре с тех пор закрыты — ADR-043,
ADR-044 и ADR-055, — и таблицы ключей выше это уже отражают. Ниже — то, что
обнаружилось при сборке схемы и в тот список не входило.

### Ключи без решённого значения или формы

1. **Где живёт `seed` — закрыто ADR-058 и ADR-066: нигде, это не ключ
   сценария.** Сид приходит параметром запуска, доходит до генератора четвёртым
   счётчиком `run_key` и в `config_hash` не входит; строка `seed` в файле —
   ошибка загрузки (§2). Хвост вопроса — чем исключался бы ключ, если бы он
   появился, — закрыт отдельно: проекция §11 п. 3, одна строка `seed: _` и одна
   в `NOT_HASHED` (ADR-066). Разбор ниже оставлен как он был написан.
   SPEC §12.4 говорит «seed в конфиге», `QUANTITIES.md` §9
   относит его к конфигу прогона, а загрузчик его не знает: сегодня сид приходит
   из CLI. Что из ADR-016 и ADR-020 следует твёрдо — сид **не** входит в
   `config_hash`, иначе тройка вырождается и развёртка по сиду теряет общую
   идентичность. Что не решено — может ли сценарий нести сид по умолчанию, и как
   тогда ключ исключается из канонической формы. Открытого вопроса на это нет.
2. **Единица `vmax` при пустом катализаторе — закрыто ADR-063: условна по
   `catalyst`.** Обороты в секунду на кубометр при `catalyst = ""`, обороты в
   секунду на моль катализатора при непустом; ключа-подписи не заводится, двух
   ключей — тоже (§6). Отказа из этого не следует: обе формы законны. Разбор
   ниже оставлен как он был написан. `QUANTITIES.md` §6 даёт
   «оборотов/(с·ед. катализатора)», а SPEC §4.7 пускает абиотические реакции
   через тот же движок с `catalyst = ""`. Множителя нет, значит единица другая, и
   какая — не сказано. Задевает каждую реакцию S0, потому что в S0 все реакции
   абиотические.
3. **Атомные массы величин из `conserved` — закрыто ADR-064: `conserved` стал
   таблицей «имя → молярная масса в г/моль».** Третья проверка ADR-033
   записывается как `molar_mass[i] ≥ (1 − ε)·Σ_e composition[i][e]·conserved[e]`
   по именам с ненулевой массой, при `ε = 10⁻⁶` из ADR-043, и получает имя
   (§10). Заряд ложится обещанным механизмом: `charge = 0.0` в `conserved`,
   `charge = -2` в знаковом `composition`. Разбор ниже оставлен как он был
   написан. ADR-033 вводит третью проверку —
   объявленная масса не меньше суммы масс отслеживаемых элементов, — а ADR-025
   специально оставляет имена в `composition` произвольными и не перечисленными в
   коде, чтобы туда ложился `charge = -2`. Валидатор не может знать массу имени,
   которого не знает, и у `charge` её нет вовсе. Либо `conserved` перестаёт быть
   списком имён и становится таблицей «имя → молярная масса», либо третья
   проверка ADR-033 неисполнима. Имени в `ACCEPTANCE.md` у неё тоже нет.
4. **`N_max` — закрыто ADR-061: граница сборки, 64.** Не ключ конфига: ключ,
   у которого нет другого действия, кроме превращения отказа в прогон,
   существует ровно для того, чтобы его подняли. Живёт в
   `crates/liminis-core/src/process/diffuse.rs` рядом со `STABILITY_LIMIT`
   (§7). Закрыл его ADR-061, а не ADR-062: тот сделал пункт **применимым**,
   впервые дав, чем считать `n` для энтальпии, и прямо сказал, что порога не
   называет. Разбор ниже оставлен как он был написан. ADR-030 требует, чтобы
   поле, которому нужно больше `N_max`
   подшагов, огрубило `lod` или решалось до стационара, и прямо говорит, что
   число придётся назвать. Оно не названо, и не решено даже, ключ это конфига или
   граница сборки рядом с `S_MAX` и `R_MAX`.
5. **`k` в оседании — закрыто ADR-067: выводится из радиуса, `k = 2r²/9`, м².**
   Ключом не становится вовсе: значение `2.2·10⁻¹¹` не имеет читаемого
   прообраза, а рядом с ключом `settling_radius` развилка «радиус или диаметр»
   превращается в вопрос, на который читатель отвечает. Через диаметр то же есть
   `k = d²/18`, и запись `r²/18` под именем радиуса дала бы скорость ровно
   вчетверо меньше истинной. Разбор ниже оставлен как он был написан.
   SPEC §4.5 задаёт `w = k·(ρ−ρ_среды)·g/μ`.
   `QUANTITIES.md` §4 объявляет `w_sed` и `μ`, а этот `k` не объявляет; в отличие
   от жёсткости давления, у него нет даже адреса в открытых вопросах.
6. **Резервуар для грани `exchange` — закрыто ADR-059: секция
   `[boundary.reservoir]`.** Величин оказалось три, а не две: концентрация
   каждого вещества снаружи, температура снаружи и скорость обмена (§4).
   Разбор ниже оставлен как он был написан. Канал `BOUNDARY_EXCHANGE`
   двусторонний
   (SPEC §7), значит внешняя сторона обязана иметь состав и скорость обмена. Ни
   того ни другого не объявлено, а `boundary_outflow_appears_in_channel_counter`
   проверяет счётчик, не источник.
7. **Законные значения `energy_from` — закрыто ADR-059: имена замкнутого
   перечисления каналов либо пустая строка.** В S0 законна только пустая;
   `"LIGHT"` из SPEC §5 незаконно, потому что свет уже зачислен в энтальпию
   шагом `i′` (§6). Разбор ниже оставлен как он был написан. SPEC §5 показывает
   `"LIGHT"`, SPEC §7
   перечисляет каналы под другими именами. Множество не зафиксировано, а
   энергетическая проверка при загрузке обязана его знать.
8. **Плотность растворённого вещества — закрыто ADR-067: ключом стал
   парциальный мольный объём.** `V_occ` складывает объёмы, а не делит массы,
   и из него уходят и `molar_mass`, и множитель `10⁻³`; знак `V̄` выражает
   электрострикцию, `V̄(H⁺) = 0` законен (§5, §9). Разбор ниже оставлен как он
   был написан. `V_occ` из SPEC §3 суммирует `m/ρ` по
   всем веществам, включая растворённые, где `ρ` физически есть парциальный
   мольный объём. Ключ объявлен (`QUANTITIES.md` §4), значение для растворённой
   формы — нет.
9. **Коэффициент диффузии поля энтальпии — закрыто ADR-062: ключ
   `thermal_diffusivity` у записи `[[field]] id = "enthalpy"`.** Шесть подшагов
   ADR-030 перестали быть цитатой и стали вычислением (§7). Разбор ниже оставлен
   как он был написан. `n = ⌈6·D·dt/dx²⌉` считается на поле
   (ADR-030), `diffusivity` объявлено на вещество (§5), а энтальпия не вещество;
   строки для тепловой диффузии нет и в `QUANTITIES.md`. Шесть подшагов, которыми
   ADR-030 обосновывает огрубление LOD, сегодня невоспроизводимы, и
   `every_n_ticks_on_diffusive_field_is_rejected` применить к энтальпии нечем.
   Открытого вопроса на это нет — то есть его придётся завести, а не сослаться.
10. **Рабочий диапазон энтальпии — закрыто ADR-062: `t_min` и `t_max` в
    кельвинах, `k_E` системой трёх неравенств.** Не парой «типичное —
    максимальное» в джоулях: джоуль на ячейку знает про воксель, а кельвин нет.
    Для реестра SPEC §2.3 окно при `i32` пусто, при `i64` — `[61, 67]`, берётся
    верх (§9). Разбор ниже оставлен как он был написан. После ADR-044
    теплоёмкость объявлена на вещество, а сценарий объявляет `T_ref`, поэтому
    диапазон энтальпии выводится из диапазона температур — но сам диапазон
    температур ключом не объявлен, и вывести масштаб по-прежнему не из чего.
    Разбор ниже оставлен как он был написан. Масштаб энергии выводится «от рабочего
    диапазона энтальпии» (ADR-035, ADR-039), но ключей, аналогичных
    `typical_conc` и `max_conc`, у энтальпии нет. Без них не получаются ни `k_E`,
    ни `units_per_joule`, а значит и `ν_E = ΔH · 2^(k_E − e_r)` (ADR-041):
    `reaction_energy_delta_is_integral_after_load` требует, чтобы валидатор назвал
    наведённую относительную ошибку числом, а числу неоткуда взяться. Это отдельная
    дыра от A-11: там `c_p` и опорное состояние, здесь диапазон.
11. **Отсутствие записи `[[process]]` — закрыто ADR-065: означает умолчание
    процесса, а не его отсутствие.** Перечень замкнут и живёт под `process/`,
    умолчание объявляет сам процесс рядом со своим инвариантом, полный список
    материализуется до хеширования. Ловушка названа в §7: удаление записи больше
    не выключает процесс. Разбор ниже оставлен как он был написан.
    Умолчание `enabled = true` описано,
    поведение процесса без записи — нет, и от развилки зависит, замкнут ли список
    процессов и применимы ли к нему умолчания до хеширования (§7, §11 п. 2).
12. **Механизм исключения `[[calibration]]` из хеша — закрыто ADR-066: явная
    проекция `Hashed<'a>`.** Отдельный заимствующий тип на 11 корневых полей с
    исчерпывающей деструктуризацией; исключаемое перечисляется константой
    `NOT_HASHED`. `skip_serializing` отвергнут: у `Config` одна реализация
    `Serialize`, и атрибут ломал бы её для всех потребителей сразу (§11 п. 3).
    Разбор ниже оставлен как он был написан. ADR-038 исключает секцию,
    §11 п. 3 объявляет канонической формой сериализацию всей структуры, и одно с
    другим не сходится: нужен либо отдельный тип для хешируемой проекции, либо
    `skip_serializing` ценой round-trip. Тот же вопрос стоит над `seed` (п. 1), и
    ответ у них, вероятно, один.

### Расхождения между документами

13. **`enthalpy` реакции: Дж или кДж — закрыто, джоули.** Победила сторона, с
    которой сходится остальной корпус: теплоёмкость и энтальпия образования
    объявлены в джоулях (ADR-044), и одна величина в другой приставке — ошибка,
    ждущая своего часа. Пример SPEC §5 переписан на `4.95e7`. Разбор ниже
    оставлен как он был написан. `QUANTITIES.md` §6 объявляет Дж/оборот,
    пример SPEC §5 подписан «кДж» и содержит `49500` — число, осмысленное только
    как килоджоули. Множитель в тысячу в величине, которая с ADR-041 округляется
    в `ν_E` при загрузке.
14. **`molar_mass`: кг/моль или г/моль — закрыто, граммы.** Так во всей таблице
    SPEC §2.3 и в числах ADR-043; исправлен `QUANTITIES.md`. Разбор ниже оставлен
    как он был написан. `QUANTITIES.md` §2 объявлял кг/моль,
    таблица SPEC §2.3 напечатана в г/моль и называет колонку именем ключа.
    Ошибка при переносе не ловится ни одной из шестнадцати проверок: массовый
    баланс — отношение. Разъедется `V_occ`.
15. **Знак в `composition` — закрыто ADR-064: тип знаковый, `i32`.**
    Отрицательное значение при этом законно только у величины с нулевой массой в
    `conserved`: иначе знак работает как скидка к третьей проверке и покупает
    право объявить массу меньше настоящей (§5, §10). Разбор ниже оставлен как он
    был написан. `QUANTITIES.md` §2 объявляет тип `u16`, ADR-025
    требует, чтобы тем же механизмом ложился `charge = -2`. Беззнаковый тип этого
    не позволяет.
16. **Энтальпия образования на вещество — закрыто ADR-044.** Объявляется ключом
    `enthalpy_formation` при 298.15 К, и объявленная энтальпия реакции сверяется
    против `Σ νᵢ·ΔH_f,ᵢ`. Разбор ниже оставлен как он был написан.
    ADR-028 называет её среди появляющихся
    величин, `QUANTITIES.md` строки для неё не имеет — там есть только `c_p`.
17. **`scale_underflow_is_rejected` — остаётся открытым.** Описание теста в
    `ACCEPTANCE.md` называет
    механизм, который ADR-039 упразднил; после вывода масштабов разрешение от
    `dx` не зависит (§10). Ни одна из записей ADR-056 … ADR-069 этого имени не
    касается: они добавляли отказы, а не пересматривали существующие. Пока имя
    остаётся, за ним стоит окно `dx` из ADR-002, и это надо либо записать
    решением, либо имя снять — но не молча.
18. **Выветривание — закрыто ADR-046.** Уравнение есть `MINERAL → 20 FE2 + P_MIN`,
    а масса `MINERAL` становится 1211.871 г/моль: формульная единица Fe₂₀PO₄,
    выдуманный минерал вместо породы, зато без пятнадцатого вещества. Разбор ниже
    оставлен как он был написан. Прежде `MINERAL → P_MIN + FE2` (SPEC §4.7) не
    сходилось по массе:
    слева `~6.2·10⁴` г/моль, справа `20·55.8 + 95.0 = 1211`. Формульная единица
    `MINERAL` подобрана так, чтобы примеси железа и фосфора выражались целыми, а
    остальная масса на правой стороне не представлена ничем. Реакция, названная в
    S0, отвергается собственной проверкой ADR-033 при любом допуске A-10, пока в
    реестре нет остаточного продукта.
19. **`every_n` против `every_n_ticks` — закрыто, `every_n_ticks`.** Так в §1.5,
    §1.7, §8, ADR-030 и в имени теста; исправлен SPEC §4.1. Разбор ниже оставлен
    как он был написан. Контракт плагина в SPEC §4.1 называл
    поле `every_n`, SPEC §1.5, §1.7, §8 и ADR-030 — `every_n_ticks`, и это же имя
    стоит в имени теста. Схема взяла второе как большинство; расхождение
    остаётся, и документ, называющий г/моль против кг/моль, обязан назвать и это.
20. **Свёрнутое условие представимости — закрыто ADR-042: `2²⁸·β`.** Разбор ниже
    оставлен как он был написан, потому что он и привёл к записи в журнале.
    Прежде ADR-039, SPEC §2.2
    и `ACCEPTANCE.md` писали `sᵢ · max_conc,ⱼ / typ_conc,ᵢ < 2²⁸/β`. Из подстановки
    `kⱼ ≥ e_r` получается противоположный множитель:
    `2²⁸/(max_conc,ⱼ·V) ≥ sᵢ/(β·typ_conc,ᵢ·V)`, то есть
    `sᵢ · max_conc,ⱼ / typ_conc,ᵢ ≤ 2²⁸·β`. Три независимые сверки дают тот же
    ответ. Проза ADR-039 говорит «примерно двадцать двоичных порядков» — это
    `2²⁸·2⁻⁶ = 2²²`, а не `2³⁴`. Направление зависимости от `β` в записи через
    деление перевёрнуто: ADR-039 утверждает, что малое `β` делает систему
    несовместной, а `2²⁸/β` при малом `β` границу поднимает. И арифметика ADR-040
    сходится только с умножением: пара «вода — протон» даёт
    `13 · 55500 / 10⁻⁴ = 2^32.75`, что превышает `2²²` ровно на заявленный там
    промах `2¹¹`, а порога `2³⁴` не достигает вовсе — то есть при записи через
    деление реестр §2.3 условие **не** нарушает, вопреки прямому утверждению
    ADR-040. Валидатор, написанный по букве, примет конфиги, которые обязан
    отвергнуть. Схема оставляет в §10 первичное неравенство `kᵢ ≥ e_r`, а не
    свёрнутую форму, и это правильно независимо от исхода: ADR-042 предписал
    валидатору проверять именно первичные неравенства, потому что свёрнутая форма
    из-за округлений верна с точностью до множителя два.
21. **Сколько отказов называют пару — закрыто, два из трёх.** `ACCEPTANCE.md`
    исправлен. Разбор ниже оставлен как он был написан. Прежде `ACCEPTANCE.md`
    относил к парным все три
    отказа из ADR-039, но `substance_dynamic_range_over_2e14_is_rejected`
    сравнивает `max_conc` и `typical_conc` одного вещества и реакции не знает.
    Парных два (§10). Контракт сообщения об отказе задаёт схема, поэтому счёт
    важен: сообщение, обязанное назвать обе стороны, для этого теста называть
    нечего.

### Открыто после ADR-056 … ADR-069

Два пункта заведены этой пачкой, и оба про числа, которых не называет ни один
документ. Нумерация продолжает список, а не вставляется в него: ссылки вида
«§13 п. N» стоят и в этом документе, и в ADR-057, ADR-058, ADR-061, ADR-062,
ADR-066 и ADR-067, и перенумерация молча увела бы каждую из них на чужой пункт.
По той же причине закрытые пункты выше помечены, а не вычеркнуты, хотя ADR-062 и
ADR-063 пишут «вычёркивается».

22. **Паритет полос диффузии не определён семью веществами из четырнадцати.**
    ADR-057 сделал восстановление инварианта границы процесса зависящим от
    чётности числа подшагов каждой полосы: копируется меньшая по числу полос
    группа паритета. Порог между `n = 1` и `n = 2` стоит на
    `D = dx²/(6·dt) = 1.67·10⁻⁹ м²/с`, и H₂S с CH₄ объявлены при `1.6·10⁻⁹` —
    в четырёх процентах под ним, то есть калибровочный сдвиг диффузии переносит
    полосу через паритет и меняет счёт копий, не сказав ни слова. Хуже, что
    коэффициентов `WATER`, `N_MIN`, `SO4`, `DET_L`, `DET_R`, `BIOMASS` и
    `MINERAL` не объявляет ни один документ — SPEC §1.7 называет `D` ровно для
    семи веществ реестра, — значит паритет семи полос из четырнадцати сегодня не
    определён ничем. Первой в этом списке стоит вода: единственная 64-битная
    полоса, чей паритет двигает не проценты, а 16.78 МБ за тик. Отсюда
    обязанность загрузчика печатать восстановительный трафик в байтах на тик
    рядом с числом подшагов (§9) — но сама дыра закрывается объявлением `D`, то
    есть данными, а не отчётом.
23. **Числа и имена, которых корпус не называет.** Отдельный пункт нужен потому,
    что это адрес: `TODO` в §12 обязаны на что-то ссылаться, а придуманное
    правдоподобное число неотличимо от решённого и переживёт того, кто его
    поставил.
    - **`c_p` и `enthalpy_formation` ни для одного вещества.** ADR-044 решил
      ключ и единицу, чисел не назвал; SPEC §2.3 таких колонок не имеет,
      `QUANTITIES.md` их не печатает. Без `c_p` не считается `C_cell`, то есть
      не выводятся ни `k_E`, ни `units_per_joule` для конкретного сценария.
      **С ADR-081 приманка переехала под инвариант, и это прямая цена решения.**
      `enthalpy_formation` **нереагирующего** вещества стала несущей: вода даёт
      99.84 % левой части энергетического инварианта и 72 % зачисления на грани
      `exchange`, а сверить её `h_f` не с чем — сверка ADR-044 идёт по реакции, а
      вода не участвует ни в одной. Опечатка в этом числе двигает и левую часть,
      и счётчик канала, молча, без единой падающей проверки; механизма против
      этого запись не предлагает и говорит об этом прямо.
    - **`partial_molar_volume` для `H2S` и `O2`.** ADR-067 печатает четыре
      значения — `SO₄²⁻ ≈ 1.4·10⁻⁵`, `H⁺ = 0` точно, `PO₄³⁻ ≈ −4.0·10⁻⁵`,
      `Fe²⁺ ≈ −2.4·10⁻⁵ м³/моль`, — и эти два в них не входят.
    - **Пять умолчательных масс `conserved`.** ADR-064 печатает `C`, `N` и `Fe`;
      `P` и `S` восстановлены здесь из его же сверки `P₄S₃` (§2), а самой
      умолчательной таблицы не печатает ни один документ.
    - **ASCII-имя и значение плотности среды — закрыто (ADR-085).** Имя —
      `rho_medium`, секция — `[physics]` (§4а), умолчание — `1000.0 кг/м³`,
      выведенное из собственного реестра проекта: `999.848` по `typical_conc` и
      `molar_mass` воды, `996.97` по её `partial_molar_volume`, обе разницы
      внутри температурной полосы 1.18 %.
    - **Значение и статус `g` — закрыто (ADR-085).** Ключ `physics.g` с
      умолчанием `9.80665 м/с²`, чем отменено следствие ADR-069 в части `g`
      (само решение и исключение `α_T` и `ρ₀` в силе). Пункт был заведён затем,
      что число здесь правдоподобно до неразличимости — `9.81` выглядит решением
      и им не является, — и закрыт он выбором по происхождению: `g_n` есть точно
      определённая величина CGPM 1901, `9.81` — округление без источника.
      Разница `0.034 %` целиком съедается калибровкой скорости
      осадконакопления, поэтому по следствию выбирать было нельзя.
    - **Идентификатор процесса поля скоростей.** ADR-069 говорит «запись
      процесса поля скоростей» и строки `id` не печатает; `velocity_field` в
      §12 — предложение, а не решение.
    - **Умолчания `enabled` пяти процессов S0.** ADR-065 отдал их коду под
      `process/`, ADR-069 назначил своё (`false`) и оговорил, что умолчание
      `advection` обязано быть `false`, иначе `hello.toml` перестанет
      грузиться; ADR-076 назначил умолчание света (`false`), и **причина, которую
      он назвал, пачку не пережила** — «вход без стока, счётчик которого его не
      вмещает» неверно обеими половинами после ADR-084 (сток есть, это грань
      `exchange`) и ADR-083 (счётчик `i128`). Умолчание при этом не
      переоткрывается ни одной из двух записей и держится тем, что шаг `a` не
      диспетчеризуется: `enabled = true` по умолчанию отвергал бы каждый сценарий
      репозитория при сборке тика, потому что меры затухания не назначил никто
      (`process/light.rs`); ADR-082
      назначил умолчание давления (`false`) временным отказом по пяти
      названным замкам; ADR-085 назначил умолчание оседания (`false`) — и не
      временно, а по разобранному выбору: переворот в `true` сделал бы
      `physics.mu` обязательной для каждого сценария репозитория, потому что
      фаза строит скорость по всем полосам и проверяет вязкость до радиуса.
      Остальные пять не назначены ничем. До пяти, а не до шести: ADR-082
      уменьшила счёт с семи до шести, и два уменьшения последовательны, а не
      складываются.
    - **Обязательность параметров света и давления — закрыто.** У света
      предикат есть с ADR-076: `i_surface` обязателен при включённом процессе, и
      умолчание `enabled` назначено. У давления — с ADR-082: `theta_max`
      обязателен при включённом процессе, умолчания не имеет, окружён окном
      (`6·Θ_sup ≤ theta_max ≤` потолок по горизонту) и строкой отчёта, а
      жёсткость `k` перестала быть и ключом, и величиной, потому что при выводе
      подвижности сокращается. Осталась помеченной только четвёрка
      `k_w … k_m`, и это другой вопрос: `process/light.rs` сделал `k` строкой
      таблицы аттенюаторов, а не четвёркой ключей.
    - **Что ADR-082 не закрывает, хотя стоит рядом.** Пустое окно достижимо
      законным сценарием — пол выше потолка при `Θ_sup/Θ_typ > 402` на 64³, а
      ADR-039 разрешает динамический диапазон до 2¹⁴, — и ни текста отказа, ни
      указания автору («грубить сетку? сужать `max_conc`?») корпус не даёт;
      порядок двух проверок решает, какое сообщение автор увидит. И `theta_max`,
      выписанный на **выключенной** записи давления, парсится, доезжает до
      канонической формы и с окном не встречается вовсе — ровно та же дыра, что
      у `u_conv_max` на выключенном поле скоростей, унаследованная сознательно.
    - **Рабочее значение `u_conv_max`.** Корпус даёт границу 16.7 мкм/с при
      `dx = 100 мкм` и `dt = 1 с` и прямо говорит, что 50 мкм/с не грузится;
      рабочего числа не называет.
    - **`conc_out` и `t_out` сценария.** Это данные того же рода, что
      `typical_conc`, и ADR-059 запрещает наследовать их умолчанием от домена;
      выписанные в §12 числа — заготовка под калибровку, и подписаны там именно
      так. Из корпуса известен только порядок `k_ex`.

### Открыто при написании валидатора

Три пункта заведены сборкой `crates/liminis-core/src/config/validate.rs`.
Нумерация продолжает список по тому же правилу, что и предыдущая пачка: ссылки
вида «§13 п. N» стоят в шести записях журнала, и вставка увела бы каждую из них
на чужой пункт.

24. **Форма допуска энергетической сверки ADR-044.** Запись говорит «допуск
    здесь такой же выведенный, как в ADR-043, и по той же причине», но ADR-043
    выводит `ε · M_оборота` **и** сверх того стережёт сам допуск снизу — он
    обязан быть меньше наименьшей молярной массы среди веществ с пустым
    составом. Энергетического двойника корпус не называет ни у опорной величины
    (`Σ|sᵢ·ΔH_f,ᵢ|`? `|ΔH_r|`? `C_cell`?), ни у второй половины правила. В коде
    стоит `TODO(enthalpy-tolerance)`: взята ближайшая структурная аналогия,
    `ε` от суммы модулей слагаемых, с тем же `MASS_EPSILON`, а не со вторым
    литералом. Пока опорная величина не названа, проверка
    `reaction_enthalpy_disagreeing_with_formation_enthalpies_is_rejected`
    ловит промах в тысячу и не обязана ловить промах в единицу. **ADR-081 этот
    пункт не закрывает** — опорная величина сверки ADR-044 остаётся неназванной,
    — но перестаёт быть единственным местом, где живёт энергетический допуск:
    внутреннее тождество `Σ ν_s·w_s + ν_E = 0` точное и допуска не требует вовсе,
    а новая сверка `−Σ ν_s·w_s` с объявленной `enthalpy` берёт `MASS_EPSILON` от
    самой объявленной величины — третье заимствование того же числа, и оно
    выбрано структурной аналогией ровно так же, как `enthalpy_tolerance`.
25. **Во что разрешается `requires.field` — закрыто (ADR-073).** Закрыто
    операционно, а не ответом: непустой `requires` стал ошибкой загрузки, и ни
    один законный конфиг имени больше не несёт, поэтому разрешать нечего.
    Перечень идентификаторов полей, их единицы и их регистр запись **не**
    назначает: единственное число корпуса, `min = 0.02`, между двумя
    прочтениями расходится в тысячи раз и не калибруется ни против чего, а
    перечень «свет, температура, pH» не покрывает случая, ради которого `max`
    вообще есть в схеме, — ингибирования веществом, которое реакции не вход.
    Поведенческая половина осталась открытым вопросом A-14: не «во что
    разрешается имя», а «какие ворота».
26. **Отказ ли `advection.enabled = true` при выключенном поле скоростей.**
    Ни одно решение этого сочетания не разбирает. Условие Куранта при нём
    остаётся без входа вовсе: конфиг грузится, шаг `c` идёт, переносить нечем.
    ADR-069 назначил умолчание `enabled` поля скоростей (`false`) и оговорил,
    что умолчание `advection` обязано быть `false` тоже, — но это оговорка про
    умолчания, а не про сценарий, выписавший `true` руками. Валидатор сегодня
    такой конфиг принимает, и это отражение пробела, а не решение.

## Отдельный Cell-Chamber Формат 1

Сценарий `configs/scenarios/cell-chamber.toml` читается только командой `cells`
через `micro::config`, а не воксельным загрузчиком. Все типы запрещают неизвестные
ключи, canonical TOML включает весь сценарий; seed остаётся параметром запуска.
Существующие canonical eco-конфиги и их hash от этого не меняются.

| Секция | Объявления и единицы |
|---|---|
| Корень | `chamber_format = 1`, `name`, `dt` (s), `extent_fraction` (безразмерный), `conserved` (g/mol) |
| `chamber` | `volume_m3`, `temperature_k`, `max_cells`, `medium_exchange_per_s` (1/s) |
| `growth` | ID, входы/выходы (целая молярная стехиометрия), BIO, ограничивающий субстрат, `enthalpy_j_per_extent` (J/mol extent) |
| `death` | `detritus_substance`; BIO и DET имеют одинаковый состав и выведенный масштаб |
| `genome` | Границы kinetics, вероятность мутации при рождении, шаг 1, множители скорости и цены сродства |
| `founder` | Число настоящих клеток, `structural_mass_mol`, `internal_energy_j`, вложенный геном |
| `founder.genome` | Kinetics, `max_growth_rate_per_s`, `uptake_km_mol_m3`, `division_mass_mol`, `maintenance_power_w`, целая capture fraction, `division_energy_j`, `starvation_tolerance_s` |
| `initial.concentration`, `medium.concentration` | Отображение ID в mol/m3; свободный BIO запрещён |
| `substance` | Существующие объявления веществ: состав, типичная/предельная концентрация, энтальпия образования, теплоёмкость, объём |

Обмен выполняет не более выведенного целого `max_delta_per_tick` на вещество,
двигаясь к целевому пулу; фактический перенос кредитуется. Это ограниченная
релаксация к резервуару, не spatial diffusion и не постоянный расход chemostat.
Параметры обслуживания, деления и энергетического захвата наследуются целиком;
на этой ступени мутирует только bounded kinetics. `max_cells` является явным
предохранителем с остановкой, а не скрытым правилом подавления деления.

Множители `genome.speed_factor_per_step` и `genome.affinity_cost_per_step`
конечны: первый строго больше 1, второй строго больше первого. Быстрый
генотип обязан платить ухудшением сродства; рост без этой цены отвергается
как при разборе сценария, так и при проверке runtime-конфигурации.

Оба крайних kinetics-фенотипа должны иметь положительные конечные скорость
и Km; Km также обязан оставаться положительным и конечным после свёртки в Q.
Положительные физические цены обслуживания и деления не могут округляться
в ноль целых единиц энергии. Явно объявленный ноль остаётся допустимым.
`starvation_tolerance_s` переводится в `ceil(seconds / dt)` полностью
допускаемых интервалов неоплаченного обслуживания; клетка погибает на следующем
неоплаченном интервале. Сохранение завершённого тика отвергается, если живой
клетке приписаны больший starvation clock, возраст меньше clock или голодание
при положительном энергетическом запасе/нулевой цене обслуживания.

Внутренний chemistry-scale shim нужен только для проверки химии и вывода единиц.
В нём задана положительная thermal diffusivity `1e-12` только для существующего
валидатора шкал: пространственного теплового поля камеры нет, shim не исполняет
диффузию. Температура камеры остаётся температурой идеальной ванны.

## Opt-in пространственная клеточная камера (ADR-108)

`chamber_format = 2` допускают только явные live entrypoints. Исторические
`load/parse/validate/derive`, exporter и LAB остаются strict format 1.
`configs/scenarios/cell-chamber-physical.toml` — прототип пассивного point
transport; химические ресурсы остаются общими well-mixed пулами.

| Ключ | Единица | Условие |
|---|---|---|
| `chamber.spatial.dimensions_m` | m, три длины | Все положительные finite; finite positive `2L`; объём `(Lx·Ly)·Lz` представим |
| `chamber.spatial.viscosity_pa_s` | Pa·s | Положительная finite |
| `founder.genome.spatial.radius_at_division_m` | m | Положительный finite hydrodynamic radius |
| `founder.genome.spatial.mobility_scale` | безразмерная | finite `[0,1]`; ноль сохраняет coordinate bits |

Format 2 требует обе spatial секции и запрещает отдельный `volume_m3`;
format 1 требует прежний объём и запрещает spatial declarations. Параметры
radius/mobility наследуются без новой мутации. Transport seed выводится из
полного user seed; отдельного UI источника случайности нет.

Finite/range/budget отказ во время transport атомарно отвергает весь tick.
Coordinate allowance ADR-108 не является bound ошибки coefficient/libm или
долгосрочного дрейфа. Проверки: `micro::config::spatial_tests` и
`micro::transport::tests`; legacy canonical fixture остаётся побайтной.
