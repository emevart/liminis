# S0: рабочее ядро и первая картинка — план реализации

> **Для агентов-исполнителей:** этот план исполняется воркфлоу
> `.claude/workflows/s0-slice.js` — по одной задаче на агента, тест сначала,
> независимая проверка после. Задачи сгруппированы в волны; внутри волны файлы
> не пересекаются, волны идут по порядку.

**Цель.** Довести проект до состояния, в котором мир считается, оба ledger'а
сходятся точно, и одна команда поднимает вьюер, где на этот мир можно смотреть и
где прогон можно остановить.

**Подход.** Порядок задан зависимостями, а не удобством: сначала то, без чего
остальное пришлось бы адресовать вслепую — реестр веществ, вывод масштабов,
каналы. Потом ядра, по одному на файл, каждое со своим приёмочным тестом. Потом
оркестрация, потом наблюдаемость, потом картинка.

**Стек.** Rust 1.97.1 (закреплён в `rust-toolchain.toml`), никаких новых
зависимостей. Вьюер — `std::net` и один HTML-файл.

## Глобальные ограничения

Действуют на каждую задачу; в тексте задач не повторяются.

- **Форма ядра.** Всё под `crates/liminis-core/src/kernels/` —
  `fn kernel(src: &[..], dst: &mut [..], p: &Params, idx: u32)`, переводимое в
  WGSL построчно. Запрещены `self`, трейты, дженерики по поведению, замыкания,
  `Vec`, `Box`, `dyn`, `HashMap`, рекурсия, аллокации, чтение из буфера записи,
  зависимость результата от порядка обхода (ADR-015, ADR-034).
- **Gather, а не scatter.** Воксель пишет только в свою ячейку. Сохранение
  следует из `flux(a, b) == -flux(b, a)` при любых входах.
- **Никаких голых операторов над `Q`.** Только обёртки. Переходов между `M` и
  `Q` ровно три: `q_conc`, `m_delta`, `xi` (ADR-022, ADR-060).
- **Округление половин от нуля** везде, кроме экстента реакции: там
  стохастическое (ADR-027).
- **Целые количества, единица молярная.** Масштаб и разрядность выводятся при
  загрузке, не назначаются (ADR-004, ADR-026, ADR-039, ADR-040).
- **`WORLD_FORMAT_VERSION`** двигается один раз на волну, если волна тронула
  `configs/**`, `kernels/**` или `process/**` (ADR-020).
- **`docs/SPEC.md` и `docs/NORTH_STAR.md` не правятся** (ADR-032). Расхождение —
  запись в журнал или строка в `ACCEPTANCE.md`.
- **Комментарии по-английски**, объясняют «почему так», а не «что делает
  строка». Планка — `numeric/convert.rs` и `kernels/diffuse.rs`.
- **Величину, которой нет в корпусе, не выдумывать.** `TODO` с объяснением, что
  именно не решено и где решается.

> **Зависимость от пачки ADR-056 … ADR-069.** Сигнатуры ниже записаны по
> предложенным решениям. Если судья переписал решение, фаза «Контракт» в
> `s0-slice` пересобирает задачу по итоговой записи — журнал старше плана.

## Волна 1. Основание

Три задачи, файлы не пересекаются.

### Задача 1.1. Сид доходит до генератора

**Файлы:** изменить `crates/liminis-core/src/numeric/rng.rs`,
`crates/liminis-core/src/numeric/mod.rs`, `crates/liminis-core/src/version.rs`.

**Записи:** ADR-058, ADR-027, SPEC §9.

**Производит:**

```rust
/// Derived once per run from the seed. Nothing downstream sees the seed itself.
#[derive(Clone, Copy, Debug, PartialEq, Eq)]
pub struct RunKey(u32);

impl RunKey {
    pub const fn from_seed(seed: u64) -> Self;
    pub const fn raw(self) -> u32;
}

/// A uniform u32 from a run key and three counters.
pub const fn rand4(run: RunKey, a: u32, b: u32, c: u32) -> u32;
```

Шаги:

- [ ] **1.** Тест `two_run_keys_give_unrelated_streams`: для сотни пар
      `(voxel, tick, reaction)` при двух разных сидах ни одно значение не
      совпадает, и распределение по 64 корзинам проходит хи-квадрат.
- [ ] **2.** Тест `the_stream_is_the_same_stream_it_was` обновляется: пять
      якорных чисел теперь от `rand4`. **Это не «обновить тест»** — это событие
      `WORLD_FORMAT_VERSION`, и комментарий рядом обязан это сказать.
- [ ] **3.** Прогнать — оба падают.
- [ ] **4.** Реализовать: `from_seed` перемешивает обе половины `u64` в один
      `u32` тем же `mix`; `rand4` — четыре раунда, по одному на аргумент.
      `rand` остаётся как `rand4(RunKey(START), a, b, c)`? **Нет** — удалить:
      два входа в один генератор дадут два потока, и однажды кто-то возьмёт не
      тот. Все вызовы переводятся на `rand4`.
- [ ] **5.** Прогнать гейт целиком.
- [ ] **6.** Инкремент `WORLD_FORMAT_VERSION` с комментарием: изменился поток
      случайных чисел, прогоны прошлой версии несравнимы.
- [ ] **7.** Коммит.

### Задача 1.2. Реестр веществ

**Файлы:** создать `crates/liminis-core/src/world/registry.rs`; изменить
`crates/liminis-core/src/world/mod.rs`.

**Записи:** ADR-056, ADR-039, ADR-040, ADR-041.

**Производит:**

```rust
/// Where a substance lives and what one of its storage units is worth.
#[derive(Clone, Copy, Debug, PartialEq, Eq)]
pub struct SubstanceSlot {
    pub width: Width,   // Bits32 | Bits64
    pub lane: u32,      // index inside its own width class
    pub k: u8,          // log2(units_per_mol), derived (ADR-039)
}

pub struct Registry { /* private */ }

impl Registry {
    pub fn slot(&self, s: u32) -> SubstanceSlot;
    pub fn lanes(&self, width: Width) -> u32;
    pub fn width_mask(&self) -> u32;        // bit s set: substance s is 64-bit
    pub fn lane_of(&self) -> &[u32];        // flat table for the reaction kernel
    pub fn n_substances(&self) -> u32;
    pub fn id_of(&self, s: u32) -> &str;
    pub fn index_of(&self, id: &str) -> Option<u32>;
}
```

Шаги:

- [ ] **1.** Тест `lanes_are_compact_within_a_width_class`: реестр из четырнадцати
      веществ, одно 64-битное — тринадцать полос в узком классе, одна в широком,
      без дыр.
- [ ] **2.** Тест `the_width_mask_names_the_same_substances_as_the_slots`:
      бит `s` установлен тогда и только тогда, когда `slot(s).width == Bits64`.
- [ ] **3.** Тест `substance_count_over_s_max_is_rejected` (имя из
      `ACCEPTANCE.md`): тридцать две записи отвергаются, и сообщение называет
      обе величины — сколько объявлено и какова граница. Учесть, что один индекс
      из `S_MAX` занят энтальпией, то есть веществ не больше тридцати одного.
- [ ] **4.** Прогнать — падают.
- [ ] **5.** Реализовать. `S_MAX = 32`, `R_MAX = 64` объявить здесь как
      `pub const` и сослаться на ADR-041.
- [ ] **6.** Гейт, коммит.

### Задача 1.3. Каналы и ledger

**Файлы:** создать `crates/liminis-core/src/ledger/mod.rs`; изменить
`crates/liminis-core/src/lib.rs`.

**Записи:** ADR-059, ADR-003, ADR-028, QUANTITIES §3.

**Производит:**

```rust
/// The boundary of the system. Closed on purpose: ADR-018 opens substances,
/// reactions and processes to contribution, not where the world ends.
#[derive(Clone, Copy, Debug, PartialEq, Eq)]
#[repr(u32)]
pub enum Channel { SolarIn, GeothermalIn, RadiativeOut, BoundaryExchange, Impact, VentBurst }

/// Counters accumulate over a whole run, not over a tick, so they are i64:
/// at 1e7 ticks an i32 overflows inside the declared horizon (QUANTITIES §3).
pub struct Ledger { /* private */ }

impl Ledger {
    pub fn new(n_substances: u32) -> Self;
    pub fn credit_matter(&mut self, ch: Channel, substance: u32, units: i64);
    pub fn credit_energy(&mut self, ch: Channel, joules: i64);
    pub fn matter(&self, ch: Channel, substance: u32) -> i64;
    pub fn energy(&self, ch: Channel) -> i64;

    /// Δ(fields + cells) − Σ(channels), per substance and separately for energy.
    /// Exact integer comparison: zero, or the run is wrong (ADR-003).
    pub fn residual_matter(&self, before: &[i64], after: &[i64]) -> Vec<i64>;
    pub fn residual_energy(&self, before: i64, after: i64) -> i64;
}
```

Шаги:

- [ ] **1.** Тест `channel_counters_do_not_overflow_at_1e7_ticks` (имя из
      `ACCEPTANCE.md`): не гоняет десять миллионов тиков, а подставляет
      граничное значение и проверяет тип. `i32` переполняется внутри
      заявленного горизонта, `i64` нет.
- [ ] **2.** Тест `a_closed_process_leaves_a_zero_residual`: поле, у которого
      сумма не изменилась и каналы пусты, даёт нули по всем веществам.
- [ ] **3.** Тест `matter_and_energy_residuals_are_separate`: канал, двигающий
      энергию и сохраняющий вещество (это свет), даёт ноль по веществу и
      ненулевой приход по энергии. Одной осью такое невыразимо — ADR-028.
- [ ] **4.** Прогнать, реализовать, гейт, коммит.

## Волна 2. Конфиг: схема, вывод, валидатор

Одна задача. Самый плотный по решениям кусок проекта: девятнадцать отказов,
четыре неравенства вывода, три класса правил без имени теста.

### Задача 2.1. Загрузчик целиком

**Файлы:** удалить `crates/liminis-core/src/config.rs`; создать
`config/mod.rs`, `config/schema.rs`, `config/derive.rs`, `config/validate.rs`,
`config/hash.rs`; изменить `crates/liminis-core/tests/config_hash.rs`.

**Записи:** ADR-025, ADR-026, ADR-027, ADR-030, ADR-033, ADR-038, ADR-039,
ADR-040, ADR-041, ADR-042, ADR-043, ADR-044, ADR-046, ADR-047, ADR-048,
ADR-061 … ADR-067. Схема ключей — `docs/CONFIG_SCHEMA.md` целиком.

**Потребляет:** `Registry`, `SubstanceSlot`, `Width` (задача 1.2).

**Производит:**

```rust
pub struct Scenario {
    pub config: Config,          // exactly what the file said, after defaults
    pub registry: Registry,      // substance -> slot, derived
    pub reactions: Reactions,    // flat tables: nu, nu_sub, begin, len, e_r
    pub substeps: Vec<u32>,      // per substance, ceil(6*D*dt/dx^2) at its lod
    pub hash: String,            // blake3:<16 hex> of the projection
}

pub fn load(path: &Path, ) -> Result<Scenario>;
```

Формулы вывода записываются в `derive.rs` дословно и с ссылкой на запись:

```text
kᵢ  = max( ⌊log₂( 2³¹/8 / (max_conc,ᵢ · V_voxel) )⌋,
           max e_r по реакциям, где i участвует )        ADR-039 + CONFIG_SCHEMA §9
e_r = ⌈ max по участникам log₂( sᵢ / (β · typ_conc,ᵢ · V_voxel) ) ⌉
νᵢ  = sᵢ · 2^(kᵢ − e_r)
ширина = i64, если количество при max_conc не влезает в i32   ADR-040
```

> **Подъём `kᵢ` до `e_r` стоит в формуле, а не в примечании к ней.** Плоская
> формула потолка даёт воде `k ≈ 52` при `e_r = 63`, то есть `kᵢ < e_r` и
> нецелое `ν`, чего в решённой системе не бывает. Автор валидатора копирует
> таблицу, а не прозу под ней.

> **Свёрнутое условие представимости — `sᵢ · max_conc,ⱼ / typ_conc,ᵢ ≤ 2²⁸·β`,
> с умножением.** ADR-042 написан ровно про эту ошибку. Валидатор при этом
> проверяет **первичные** неравенства по `kᵢ` и `e_r`, а не свёрнутую форму:
> из-за округлений вниз и вверх она верна с точностью до множителя два и
> годится читателю, а не отказу в загрузке.

Шаги:

- [ ] **1.** Тесты отказов, все девятнадцать, именами из `ACCEPTANCE.md`.
      Каждый — минимальный TOML, отличающийся от валидного одной строкой, и
      проверка, что сообщение называет виновника. Для двух из трёх отказов
      ADR-039 сообщение обязано назвать **пару** «вещество, реакция», а не одно
      имя: конфиг, в котором виновата пара, нельзя починить, глядя на одно имя.
- [ ] **2.** Тесты вывода: `extent_exponent_is_derived_from_the_scarcest_participant`,
      `storage_width_is_derived_not_declared`,
      `water_is_stored_in_64_bits_in_the_default_registry`,
      `reaction_energy_delta_is_integral_after_load`,
      `mass_tolerance_is_derived_not_declared`.
- [ ] **3.** Тесты правил без имени в `ACCEPTANCE.md`, из `CONFIG_SCHEMA.md` §10:
      ссылочная целостность (уникальность `id`, разрешимость всякого имени в
      `inputs`, `outputs`, `rate.km`, `catalyst`, `requires.field`), область
      определения (`dt > 0`, `typical_conc ≤ max_conc`, `km > 0`, …), делимость
      сетки на `2^lod` по каждой оси.
- [ ] **4.** Тесты хеша: четыре существующих плюс
      `config_hash_ignores_the_calibration_section` и
      `the_projection_covers_every_simulated_key` — последний ловит ключ,
      добавленный в схему и забытый в проекции. Без него проекция протухает
      молча, а это единственный её недостаток (ADR-066).
- [ ] **5.** Прогнать — все падают.
- [ ] **6.** Реализовать `schema.rs`: типы `serde` со `deny_unknown_fields`,
      скаляры впереди таблиц (в TOML голый ключ после заголовка таблицы не
      записать). `conserved` — таблица «имя → молярная масса» (ADR-064),
      `composition` знаковый.
- [ ] **7.** Реализовать `derive.rs` по формулам выше. Совместное решение
      системы, а не два независимых прохода.
- [ ] **8.** Реализовать `validate.rs`. Сообщение об отказе — не «конфиг
      неверен», а какое неравенство нарушено, какими числами и что с этим
      делать.
- [ ] **9.** Реализовать `hash.rs`: явная проекция, `[[calibration]]` и `seed`
      вне её по построению.
- [ ] **10.** Гейт, коммит.

## Волна 3. Мир и первые три ядра

Четыре задачи. Перед волной я создаю пустые `kernels/*.rs` и объявляю их в
`kernels/mod.rs` — иначе четыре агента правят один файл и затирают друг друга
молча.

### Задача 3.1. `World`

**Файлы:** создать `world/world.rs`; изменить `world/mod.rs`, `world/field.rs`.

**Записи:** ADR-056, ADR-057, ADR-045, SPEC §1.5.

**Производит:** `World` — поля обеих ширин, поле энтальпии на своём LOD, поле
света, накопитель энергии реакций без двойного буфера, счётчик тика; доступ к
полосе по индексу вещества через `Registry`.

Несущее: **на границе процесса передний буфер есть состояние `N` для каждой
полосы** (ADR-057). Полоса, продвинутая нечётным числом подшагов,
восстанавливается процессом.

- [ ] **1.** Тест `every_lane_is_state_n_at_a_process_boundary`: два вещества с
      числом подшагов 1 и 2, после тика обе полосы читаются из переднего
      буфера и держат то, что должны.
- [ ] **2.** Тест `a_coarse_cell_covers_exactly_its_fine_cells`: отображение
      LOD — сдвиг **по каждой оси**, а не по линейному индексу; проверить, что
      64 мелкие ячейки грубой не пересекаются с соседней.
- [ ] **3.** Прогнать, реализовать, гейт, коммит.

### Задача 3.2. Ядро адвекции

**Файлы:** создать `kernels/advect.rs`.

**Записи:** ADR-054, ADR-005, ADR-034, ADR-036, SPEC §4.2.

Несущее, и оба легко потерять:

1. **Каноническая ориентация грани.** Поток считается от меньшего линейного
   индекса к большему, соседи применяют одно и то же число с противоположными
   знаками. Если каждый воксель посчитает «со своей стороны», две стороны
   выполнят одно выражение с разным порядком операндов, `Q`-арифметика
   разойдётся в последнем бите, и антисимметрия сломается молча.
2. **Откат при нулевом градиенте.** Отношение `r` не определено, и **обе
   стороны** обязаны откатиться к первому порядку одинаково.

- [ ] **1.** Тест `flux_is_antisymmetric` для нового потока, `proptest` на
      случайных парах и скоростях.
- [ ] **2.** Тест `flux_limiter_falls_back_to_first_order_at_zero_gradient`.
- [ ] **3.** Тест `advection_never_produces_negative_amount`.
- [ ] **4.** Тест `advection_of_a_step_produces_no_new_extrema`.
- [ ] **5.** Прогнать, реализовать, гейт, коммит.

### Задача 3.3. Ядро света

**Файлы:** создать `kernels/light.rs`.

**Записи:** SPEC §4.6, ADR-028, ADR-049.

`I[z−1] = I[z] · exp( −(k_w·water + k_b·biomass + k_d·detritus + k_m·mineral)·dz )`,
один проход сверху вниз, O(N). Убыль **не исчезает**: `I[z] − I[z−1]` есть
величина производная, и зачисляет её ядро свёртки (задача 4.2), а не это.

- [ ] **1.** Тест `light_attenuation_matches_beer_lambert`: однородная среда,
      аналитическая экспонента, сходимость по `dz`.
- [ ] **2.** Прогнать, реализовать, гейт, коммит.

### Задача 3.4. Ядро оседания

**Файлы:** создать `kernels/settle.rs`.

**Записи:** ADR-067, SPEC §4.5, ADR-034.

- [ ] **1.** Тест `sedimentation_conserves_exactly`.
- [ ] **2.** Тест `a_neutrally_buoyant_substance_does_not_move`.
- [ ] **3.** Прогнать, реализовать, гейт, коммит.

## Волна 4. Реакции, энергия, давление

### Задача 4.1. Ядро реакций

**Файлы:** создать `kernels/react.rs`.

**Записи:** ADR-041, ADR-027, ADR-039, ADR-045, ADR-047, ADR-048, ADR-050;
второй скелет в `docs/ARCHITECTURE.md`.

Три несущие вещи, и все три легко потерять при переписывании:

- **Снимок один на все реакции.** Спрос считается по состоянию `N`, применение
  идёт в `N+1`. Пересчёт наличия после каждой реакции делает порядок строк в
  TOML частью семантики мира — невидимо, потому что баланс продолжает сходиться.
- **Дельты копятся локально и пишутся один раз.** `dst[at] += …` внутри цикла по
  реакциям есть чтение из буфера записи.
- **`ξ_max` считается только по входам.** Потолок выхода — гарантия валидатора
  через `max_conc`, а не кламп здесь.

- [ ] **1.** Тест `reaction_alone_conserves_each_element_exactly`.
- [ ] **2.** Тест `competition_scaling_conserves_each_element_exactly`.
- [ ] **3.** Тест `all_reactions_share_one_competition_coefficient`.
- [ ] **4.** Тест `reaction_result_is_independent_of_order_in_toml` — тот самый,
      что ловит последовательное применение.
- [ ] **5.** Тест `reaction_never_produces_negative_amount`.
- [ ] **6.** Прогнать, реализовать, гейт, коммит.

### Задача 4.2. Свёртка энергии

**Файлы:** создать `kernels/fold.rs`.

**Записи:** ADR-045, ADR-049.

Собирает **два** источника: приращение энергии реакций с мелкой сетки и
поглощённый свет, вычисляемый на лету из поля света. Второго накопителя не
заводится: поле света уже хранится на 128³, значит поглощённое — величина
производная, и хранить её отдельно значило бы держать два источника истины об
одном и том же.

- [ ] **1.** Тест `energy_fold_from_fine_to_coarse_conserves_exactly`.
- [ ] **2.** Тест `absorbed_light_appears_in_enthalpy`.
- [ ] **3.** Прогнать, реализовать, гейт, коммит.

### Задача 4.3. Ядро давления

**Файлы:** создать `kernels/pressure.rs`.

**Записи:** ADR-055, ADR-006, SPEC §3.

`P = k·(V_occ/V_voxel − 1)`, подвижность выведена из условия Куранта при
объявленном предельном переполнении. Множитель `10⁻³` в `V_occ` — часть формулы,
а не опрятность: без него давление вырождается в почти однородное, и механика
ADR-006 не запускается вовсе.

- [ ] **1.** Тест `pressure_relaxation_conserves_exactly`.
- [ ] **2.** Тест `pressure_relaxation_reaches_hydrostatic_equilibrium`.
- [ ] **3.** Тест `pressure_signal_crosses_the_domain_at_one_voxel_per_tick`.
- [ ] **4.** Прогнать, реализовать, гейт, коммит.

## Волна 5. Оркестрация

Шесть задач-процессов, по файлу на каждую; `process/mod.rs` пре-создан мной.
Каждый процесс сворачивает параметры на хосте, объявляет свой инвариант на двух
осях и владеет своими подшагами.

- **5.1** `process/advect.rs` — свёртка `u·dt/dx`, покомпонентное расщепление.
- **5.2** `process/react.rs` — плоские таблицы реакций из `Scenario`, счётчик
  тика для RNG.
- **5.3** `process/light.rs` — проход по Z, модуляция суточная и сезонная.
- **5.4** `process/pressure.rs`, **5.5** `process/settle.rs`.
- **5.6** `process/velocity.rs` — предписанное поле (ADR-069): вихри, шум,
  конвективная поправка от `∇T`, с проверкой объявленного `u_max` в debug.

Каждая: тест «процесс в одиночку сохраняет то, что обязан» — то, ради чего
ADR-018 требует включать и выключать процессы по отдельности.

## Волна 7. Наблюдаемость и начальные условия

- **7.1** `observe/mod.rs`: NDJSON, первая запись — заголовок прогона (`seed`,
  `config_hash`, `WORLD_FORMAT_VERSION`, версия тулчейна, перечень колонок).

## Самопроверка плана

**Покрытие спеки.** Каждый пункт дизайн-документа §4 имеет задачу: реестр — 1.2,
вывод масштабов и валидатор — 2.1, ядра — волны 3 и 4, оркестрация — 5 и 6,
наблюдаемость — 7, вьюер — 8. Приёмочные имена из §6 дизайна разложены по
задачам; ни одно не осталось без адреса, кроме двух намеренно вынесенных за
контрольную точку (10⁶ тиков и порог производительности).

**Заглушки.** Формулы вывода, сигнатуры и несущие свойства выписаны дословно.
Там, где стоит «реализовать», фаза «Контракт» в `s0-slice` разворачивает задачу
по коду и записям — это её работа, и она делается агентом, у которого репозиторий
перед глазами.

**Согласованность типов.** `Registry`, `SubstanceSlot`, `Width` объявлены в 1.2 и
потребляются в 2.1 и 3.1 под теми же именами. `Channel` и `Ledger` — в 1.3,
потребляются в 6.1. `Scenario` — в 2.1, потребляется в 5.x и 8.1.
