# Liminis: поручение cloud-сессии

Дата: 2026-10-04. Это передача пользовательского запроса, не изменение
замороженной спеки. Перед стартом сверить main, AGENTS.md и checkpoint.

## Режим работы

- Координатор: GPT-6.1 Sol, reasoning effort xhigh. Настройки сессии должны
  действительно соответствовать этим значениям; текст поручения сам по себе
  не переключает модель. Не подменять недоступную модель молча.
- Использовать субагентов для независимых участков и проверки. Astra
  (gpt-6-astra) - советник по архитектуре и биологии. Значимые решения
  согласовать с ним до реализации. Ограничивать число агентов по ресурсу.
- Без оверинжиниринга: каждый этап заканчивается работающим наблюдателем,
  проверками, checkpoint и отдельным PR в main из ветки codex/.
- Читать AGENTS.md, подходящие ADR и локальные инструкции. SPEC/NORTH_STAR
  и docs/archive не редактировать. ADR append-only, раздел «Отвергнуто» обязателен.
- Не менять внешнюю инфраструктуру, не запрашивать секреты без необходимости,
  не подключаться к рабочему ПК. Cloud не содержит локальные живые культуры.
  Репозиторий публичный, Apache-2.0; сайт обслуживается существующей интеграцией.
- Продолжать до проверенного результата, но не называть недоступное ревью,
  браузерную проверку или незавершённый CI успешными. Один Cargo-процесс на сборку.

## Текущее состояние

Локальный cells host - well-mixed индивидуальные клетки, точные целые балансы,
рост, деление, смерть и ограниченный наследуемый kinetics allele. Сохранение
и восстановление состояния уже существуют. Voxel host - отдельный прототип.
Клеточная камера не связана с конкретным вокселем большого мира.

Публичный site - записи существующего Rust engine, не browser/live engine.
Каталог 10k/100k/1M содержит по 201 настоящему sampled frame. При одинаковых
config/seed это одна детерминированная траектория. Каждый тик проверен; запись
не восстанавливает события между samples и не является restart checkpoint.
Координаты отображения условные. Миллион micro-тиков не означает приёмку S0.

## Первый PR: Скорость Расчёта

Пользователь разрешил ручную скорость и режим максимальной скорости по примеру
Universe Sandbox. Сейчас cells host и slider ограничены 100 ticks/s; voxel host
имеет отдельный cap 200. Это pacing адаптера, не физический dt и не предел спеки.

Сначала улучшить cells host, не менять численную модель:

1. Ручное положительное конечное значение ticks/s и отдельный режим maximum.
   Не представлять максимум как бесконечный float или dt=0. Расчёт идёт всеми
   реальными тиками, скорость меняет только wall-clock pacing.
2. Показывать заданную и измеренную скорость отдельно от dt, model time и
   поколения. Переключение rate/max не сбрасывает культуру или tick.
3. Оставить Pause, Step, HTTP чтение и checkpoint отзывчивыми при maximum.
   Не держать общий lock на неограниченной пачке и не создавать бесконечную
   очередь снимков. Частота rendering/sampling не обязана равняться tick rate.
4. Валидация NaN/Inf/нулевых/отрицательных значений. Старые checkpoints с
   конечной сохранённой скоростью должны загружаться без потери core state.
   Новая форма сохранённого pacing должна быть явно версионирована при необходимости.
5. Доказать одинаковые core-состояния, IDs, RNG и balances после одинакового
   числа тиков при разных скоростях. Проверить rate/max, Pause/Step/save/resume,
   измерить реальную release throughput на названном сценарии и оборудовании.
6. Не «ускорять» увеличением dt, пропуском ledger/physics или выключением
   safety guards. Отдельный большой horizon export не снимать лимитом молча.

## Следующие Отдельные Этапы

После первого PR вновь сверить приоритеты с пользователем и Astra:

1. Реальные persisted x/y/z клетки и физические размеры камеры. Проверяемый
   пассивный stochastic transport: единицы, deterministic cell-ID/tick/purpose
   RNG, daughter placement. Сначала dilute suspension, без adhesion/GRN/motors.
   Mobility/size - genome-derived; T/viscosity/boundaries - среда. Явно назвать
   отсутствие excluded volume, если это point/dilute model.
2. Сохранение и restart/replay exact positions, zero-mobility контроль без
   изменения старых биологических RNG streams, isotropy/zero drift/MSD6Dt
   до контакта со стеной с заранее выбранными статистическими критериями,
   boundaries и независимость от row ordering. Независимый numerics-review.
   Нужны новый ADR и форматы состояния; не выдумывать позиции старым записям.
3. Затем 2D/3D через Three.js как два вида одного настоящего состояния,
   orbit/slice/transparency и инспектор. Не анимировать hash-позиции как физику.
4. Затем локальные FOOD/O2/DET, micro solver/gather по ADR-051 и реальные
   пространственные growth fronts S1'. GRN/adhesion/развитие S2 - следующий этап.

North Star: существенные эволюционные переходы и изменение уровня отбора,
а не только большое число тиков или красивый ролик. Frozen SPEC §1.7, §6,
§12, §13 остаются ориентирами; расхождения называются явно через журнал ADR.


## Уточнение live pacing и следующие отдельные PR (2026-10-04)

Текущее пользовательское поручение уточняет первый PR: одна ручка ×N,
1× = модельная секунда за wall second, target TPS=N/dt, actual ×=measured TPS·dt,
отдельный Maximum и экранная цель 30/60 FPS. Первоначальный текст про ручные
TPS выше уступает этому уточнению. Default 90× согласован с Astra; checkpoint
каталога описывает исторический этап, не разрешение менять этот scope.

После live pacing отдельный PR: recorded playback по model timestamps с ×N
и автоматической длительностью remaining model time/N (Maximum — лишь оценка
по измеренной скорости, если уместно). Плотность реальных сохранений задаётся
при прогоне, максимум один state на tick. Старые 201 samples не превращаются
в новые состояния. Always-full million JSON может занимать десятки GB: нужны
bounded/chunked storage и delivery, без снятия safety caps. Этот этап не входит
в live PR. Затем persisted coordinates/transport с numerics-review и 2D/3D
одного настоящего состояния согласно указанным выше границам.
