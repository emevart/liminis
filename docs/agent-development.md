# Разработка Claude Code и Codex

Обновлено: 2026-09-09.

## Источники и состояние

Корневой AGENTS.md хранит инварианты, вложенный AGENTS.md в kernels/ —
численные правила. Claude загружает их через соседние CLAUDE.md.
Codex открывает инструкции затронутых дочерних каталогов до редактирования.

В дереве d21fb41 уже есть ядра, цикл тиков и локальный viewer. Это наблюдение
о наличии реализации, не объявление приёмки всей S0. Оставшиеся критерии
проверяются по ACCEPTANCE и свежему evidence. Команда run печатает идентичность
конфигурации; симуляцию и viewer запускает serve.

## Проверки по scope

Из корня checkout, версии Rust — из rust-toolchain.toml:

| Изменение | Проверка |
| --- | --- |
| Только Markdown | git diff --check, относительные ссылки и импорты, сравнение защищённых документов с базой |
| Rust | cargo fmt --all --check; cargo clippy --workspace --all-targets -- -D warnings; cargo test --workspace |
| Численные ядра/WGSL | предыдущие проверки + python scripts/check_bare_q.py + numerics-review |
| Хуки | bash scripts/test-hooks.sh; suite запускает также Cargo fmt/clippy, поэтому это не лёгкий docs-check |
| Семантика мира | WORLD_FORMAT_VERSION и guards .github/workflows/ci.yml; seed/config_hash и соответствующие acceptance/golden проверки |
| Viewer | узкие тесты изменённого пути и browser QA; release-прогон не доказывает debug LEDGER-инварианты |

На Unix Python может называться python3. В Windows используй Git Bash,
не предполагай, что системный bash.exe является Git Bash. Зависимости и Cargo
toolchain устанавливай по необходимости конкретной проверки. Не запускай
симуляции/сборки для редактирования Markdown.

## Hooks, skills и ограничения адаптеров

.claude/settings.json регистрирует frozen-docs, adr-append-only, golden-guard
и kernel-lint для Claude. Это не автоматическая защита Codex и не перехват
всех способов записи через shell. Для любого агента обязательны:

- SPEC.md и NORTH_STAR.md заморожены; docs/archive/ доступен только для чтения.
- DECISIONS.md дополняется в конце; новое ADR согласуется по
  [.claude/skills/adr/SKILL.md](../.claude/skills/adr/SKILL.md).
- Golden не переписывается ради зелёного теста. Обоснованный новый эталон —
  отдельное явное действие с review; переменная разрешения хука сама по себе
  не является доказательством корректности.
- Перед завершением сравни защищённые пути с базовым SHA. Для ADR проверь,
  что прежнее содержимое осталось неизменным префиксом нового.
- Численные проверки остаются в CI; hooks не заменяют тесты и review.

Codex-адаптер ADR находится в .agents/skills/adr/, тело процедуры единое.
Описание роли .claude/agents/numerics-reviewer.md можно передать ревьюеру
любой системы. Claude Workflow-скрипты требуют своего runtime; их наличие
не означает, что Workflow доступен в Codex. Если его нет, выполни те же
ограниченные этапы имеющимися средствами, сохранив gates и согласование ADR.

## Параллельные коллеги и передача

Значимая задача имеет результат, scope, зависимости, проверку и владельца.
Независимые сессии используют отдельные checkout и ветки. Для одной задачи
достаточны узкие subagents; отдельный отдел не создаётся ради каждого файла.
Общие Cargo-каталоги не переиспользуются через symlink между изменяемыми checkout.

Checkpoint по [шаблону](checkpoint-template.md) сохраняется в плане задачи
или отдельном docs/checkpoints/ДАТА-тема.md. Указывай проверенный SHA,
параметры воспроизведения, незакрытые критерии и следующий шаг.

## Побочные находки

Существенный вопрос, гипотезу, баг или предложение фиксируй в checkpoint либо
существующем backlog: источник/evidence, что наблюдалось и что ещё гипотеза,
влияние, зависимость, владелец следующей проверки. Найди дубликат до новой карточки.
После проверки: принять в согласованный scope/backlog, отложить с причиной
и условием возврата либо отклонить с причиной. Blocker подними сразу,
независимую задачу передай в параллельный трек. Значимые продуктовые/дизайн
решения покажи пользователю. Находка не расширяет scope и не разрешает
внешнее сообщение автоматически; issue на каждую мысль не нужен.
