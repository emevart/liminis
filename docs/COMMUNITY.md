# Сообщество и открытый код

---

## Три аудитории

Приоритет по важности — соавторы, исследователи, пользователи. Порядок появления обратный, и это стоит держать в голове при планировании.

| | Что им нужно | Что они дают | Когда придут |
|---|---|---|---|
| **Соавторы** | Понятная архитектура, тесты, границы вклада, отзывчивый мейнтейнер | Код, идеи, продолжение проекта без тебя | Последними |
| **Исследователи** | Воспроизводимость, цитируемость, честная документация ограничений | Ссылки, валидацию, вопросы, которых ты не придумал | После первых результатов |
| **Пользователи** | Ссылка, картинка через минуту, ручки для кручения | Интересные сиды, распространение, поток внимания | Первыми |

**Воронка.** Соавторы появляются у проектов, которые уже работают и на которые уже смотрят. Практически: инструмент, привлекающий соавторов, — это демо, а не `CONTRIBUTING.md`. Поэтому проектируем для соавторов с первого дня, но вкладываемся в пользовательскую поверхность раньше, чем кажется логичным.

## Границы вклада

Ядро узкое, поверхность конфига широкая. Это структурное решение, а не правило в документации.

**Принимается свободно:**

- сценарии — наборы веществ, реакций, начальных условий
- передаточные функции и визуальные пресеты
- инструменты анализа и метрики
- документация, переводы, примеры
- портирование, сборка под платформы
- тесты

**Принимается с осторожностью:**

- новые процессы среды (нужен золотой тест против аналитического решения)
- изменения в реестрах и форматах (тянут версию семантики мира)

**Практически не принимается:**

- численные ядра

Причина последнего не в собственничестве. Тонкую ошибку в потоковой схеме не поймает ни один ревьюер: физика испортится молча, прогоны продолжат выглядеть правдоподобно, и через полгода будет невозможно установить, когда результаты перестали что-либо значить. Для исследовательского инструмента это фатально.

Из этого следует техническое требование: **порог входа для нового сценария — отредактировать TOML и запустить.** Если для добавления вещества нужно тронуть код, вклад сообщества сведётся к опечаткам в README.

## Воспроизводимость как контракт

Прогон идентифицируется тройкой:

```
(seed, config_hash, version)
```

Баг-репорт без неё невоспроизводим и закрывается с просьбой дополнить. Это надо написать в шаблоне issue.

`version` включает **версию семантики мира** — отдельный счётчик, инкрементируемый при любом изменении, влияющем на динамику: константа в реакции, порядок операций в ядре, формула. Без него через год накопится коллекция результатов, про которые неизвестно, можно ли класть их на один график.

Версия кода и версия семантики мира — разные числа. Рефакторинг без изменения поведения меняет первое и не меняет второе.

## Галерея сидов

Вероятно, главный механизм привлечения. Прогон — это конфиг плюс seed, то есть килобайты. Репозиторий сценариев с картинкой и описанием «что тут интересного» превращает наблюдение в коллективное занятие.

Приём: форма в вебе → запись в базу с превью, лучшее переносится в репозиторий как отобранные сценарии.

**Требование, которое из этого вытекает:** сид должен воспроизводиться на чужой машине. Иначе галерея бесполезна. Это возвращает требование кросс-платформенной воспроизводимости, смягчённое в §9 спеки, — см. открытый вопрос C-4.

## Формальности

**Лицензия: Apache-2.0.** MIT тоже приемлем. GPL — нет: юридические отделы университетов её часто блокируют, а исследовательская аудитория нужна. Apache дополнительно даёт явный патентный грант.

**CITATION.cff в корне и DOI через Zenodo.** Неочевидно для разработчиков, но именно так исследовательский софт получает признание. Если кто-то опубликует результат на движке, он должен знать, как процитировать. Пятнадцать минут работы меняют статус с «репозиторий» на «инструмент».

**Code of Conduct** — стандартный Contributor Covenant. Скучно, но его отсутствие замечают.

**Ожидания в README, одной честной фразой.** «Исследовательский проект, отвечаю когда есть время, PR в численные ядра принимаю редко». Без этого поток issue будет создавать чувство долга, а люди будут разочаровываться.

## Что нужно к моменту открытия

Минимум, ниже которого открывать не стоит:

1. Работающий S0 с воспроизводимым прогоном.
2. Одна убедительная картинка или видео.
3. README с ответом на «что это и зачем» в первых трёх строках.
4. Готовый сценарий и команда, запускающая его без настройки.
5. `NORTH_STAR.md`, `SPEC.md`, `DECISIONS.md` — они уже есть и они сильная сторона проекта.
6. Лицензия, CITATION.cff, шаблон issue.

Хостед-демо и галерея — не к открытию, но раньше, чем кажется. Записанный или считающийся в браузере прогон по ссылке будет самым сильным инструментом привлечения из всех.
