# Численные ядра

Два правила. Оба проверяемые, оба обязательные.

## Форма ядра (ADR-015)

Ядро пишется сразу в форме, переводимой в WGSL **построчно**. Не «потом
перепишем» — с первой строки.

Сигнатура фиксирована (ADR-034), полностью — в `docs/ARCHITECTURE.md`:

```rust
fn kernel(src: &[..], dst: &mut [..], p: &Params, idx: u32)
```

Разрешено:

- функции над плоскими массивами, индексация по линейному индексу вокселя;
- обработка вокселя, независимая от порядка обхода;
- локальные скаляры, массивы фиксированного размера, `for` по диапазону.

Запрещено внутри ядра:

- `self`, трейты, трейт-объекты, дженерики по поведению;
- аллокации в цикле — вообще любые аллокации;
- замыкания, `Vec`, `HashMap`, `Box`, `dyn`, рекурсия;
- ветвление по типу и вызовы через таблицу виртуальных методов;
- знание про конфиг, время и `dx` по отдельности: параметры сворачиваются на
  хосте и приходят одним числом;
- зависимость результата от порядка обхода вокселей (двойная буферизация
  обязательна: читаем состояние `N`, пишем `N+1`).

CPU-версия — вечный эталон, а не строительные леса. После порта на GPU она
остаётся: расхождение шейдера с ней в целочисленных полях есть баг в шейдере.

## Gather, а не scatter (ADR-034)

Воксель считает своё новое значение сам, читая соседей, и пишет **только в свою
ячейку**. Никогда в чужую.

ADR-005 формулирует сохранение как «вычли у донора, прибавили акцептору», и
напрашивается ядро, применяющее поток к обеим ячейкам. Так нельзя: на GPU это
атомик на каждую грань, а результат становится зависимым от порядка.

В gather-форме сохранение следует из антисимметрии функции потока:

```
flux(a, b) == −flux(b, a)   при любых a и b
```

Сосед в том же подшаге прибавит себе ровно противоположное, сумма по домену
тождественно ноль — без атомиков и без синхронизации.

**Антисимметрия держится на правиле округления.** Половины от нуля симметричны:
`1.5 → 2`, `−1.5 → −2`. Округление вниз — нет: `floor(1.5) = 1`, но
`floor(−1.5) = −2`. Написать поток через `floor` — самый естественный способ
округлить целочисленный сдвиг, — и масса потечёт по единице на грань. Ни
компилятор, ни grep этого не увидят; ловит только тест
`flux_is_antisymmetric`, и он обязателен для каждой новой функции потока.

Единственное исключение из «пиши только в свою ячейку» — счётчики каналов
ledger: атомарное сложение, коммутативное, потому что счётчики целые.

Сохранение обязано быть верным **по построению**, а не выполняться приближённо
и проверяться тестом. Если схему можно записать так, что масса теряется, схема
неправильная.

## Никаких голых операторов над `Q` (ADR-022)

`M` — экстенсивные, учитываемые величины: массы, энергия, объём. Всегда целые.
`Q` — интенсивные и производные: концентрации, температура, скорости реакций,
экспрессия, коэффициенты, промежуточные результаты. Режимо-зависимые.

Внутри ядра над `Q` **нет голых арифметических операторов**. Только обёртки:

```
qadd  qsub  qmul  qdiv
qexp  qlog  qpow  qsqrt  qrcp  qsigmoid
```

Конверсия между классами происходит ровно в двух местах и больше нигде:

```
q_conc(mass: M, volume) -> Q      масса в концентрацию
m_delta(rate: Q, dt)    -> M      скорость в приращение массы
```

Причина, по которой правило жёсткое, а не рекомендательное: смена режима
`FLOAT`/`FIXED` должна стоить пересборки, а не переписывания ядер. Один голый
`a * b` в горячем месте — и в fixed-режиме там тихо неверный результат вместо
ошибки компиляции. Трансцендентные обязаны быть таблицами: IEEE-754 не требует
побитовой точности для `exp`, `log`, `pow`, и реализации у вендоров расходятся.

Первый рубеж защиты — сам тип: `Q` не реализует `Deref` и не раскрывает
внутреннее поле, поэтому голый оператор не компилируется. Второй рубеж — grep в
`kernel-lint`-хуке и в CI, для WGSL-шаблонов, где системы типов нет.

Таблица операций и правило округления — `docs/NUMERIC.md`.
