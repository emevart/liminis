# Liminis: инструкции агентам

Обновлено: 2026-09-09. Общий слой Claude Code/Codex — AGENTS.md и вложенные
AGENTS.md. CLAUDE.md импортирует их, общие правила не дублируются.

## Начало и координация

- Прочитай поручение, git status, ветку/HEAD и checkpoint задачи. Приоритет
  у текущих указаний пользователя с сохранением ограничений инструментов.
- Перед правкой читай ближайшие AGENTS.md; для ядер —
  crates/liminis-core/src/kernels/AGENTS.md. Карта: [docs/README.md](docs/README.md).
- Параллельные сессии ведут независимые задачи в отдельных checkout/ветках;
  subagents получают узкую задачу и владельца файлов. Один координатор
  согласует пересечения. Не переключай чужую ветку и не откатывай dirty-файлы.
- Значимую численную работу заверши независимым numerics-review.
  Протокол доступен всем агентам: .claude/agents/numerics-reviewer.md.
- Масштаб review/effort выбирай по риску; не запускай автоматически десятки
  агентов, симуляции и параллельные Cargo-сборки. Локальный viewer требует
  свободного порта и ресурса, остановка чужих процессов не подразумевается.
- Используй отдельную ветку (Codex: codex/) и PR в main.
  Публикация crate или изменение внешней инфраструктуры требует своего scope.
- Проверки и различия адаптеров: [agent-development](docs/agent-development.md).
  В конце этапа обнови checkpoint по [шаблону](docs/checkpoint-template.md).
  Уже данное разрешение сохраняй с источником и scope, не спрашивай повторно.
- Секреты, персональные модели, контекст и права инструментов не хранятся
  в shared config. Проза изменений по-русски, идентификаторы как в коде.

Воксельный симулятор био-экосистемы для изучения существенных эволюционных переходов.

## Прежде чем предлагать архитектурное решение

Прочитай `docs/DECISIONS.md`. Журнал фиксирует принятые и отвергнутые варианты; ищи относящиеся
к задаче ADR до предложения нового решения.

- Если предложение противоречит ADR — **назови номер и скажи прямо**: «это отменяет
  ADR-0NN, потому что …». Не обходи молча, не переизобретай уже отвергнутый вариант.
- **Спека заморожена** (ADR-032). Порог пройден: в `crates/liminis-core/src/kernels/`
  десяток файлов, поэтому `docs/SPEC.md` и `docs/NORTH_STAR.md` не редактируются
  вовсе — ни для приведения в соответствие, ни для дополнения. PreToolUse-хук
  проверяет состояние `kernels/` сам и откажет в правке. Расхождение с замороженной
  спекой не правится, а называется расхождением: запись в журнал, операционная
  форма — в `docs/ACCEPTANCE.md`.
- Новая идея идёт в `docs/OPEN_QUESTIONS.md`, не в SPEC.
- Новое решение — запись **в конец** `docs/DECISIONS.md` через `/adr`, с обязательным
  разделом «Отвергнуто». Существующие записи не правятся: отмена решения оформляется
  новой записью со ссылкой на отменяемую.
- `docs/archive/` — вытесненные черновики. Они противоречат актуальной спеке,
  ссылаться на них нельзя.

## Инварианты

- **Закрытый учёт** (ADR-003, ADR-028). Вещество и энергия приходят и уходят только
  через именованные каналы со счётчиками. Инвариант каждого тика — отдельно по веществу,
  отдельно по энергии, и обе половины сегодня выглядят не так, как в ADR-003:

  ```
  вещество: Δnₛ == Σ_c credited(c, s) + Σ_r ν_{r,s}·Ξ_r        (ADR-080)
  энергия:  Δ(H_поля + Σₛ wₛ·nₛ) == Σ_c credited(c)            (ADR-081)
  ```

  Второе слагаемое справа у вещества — суммарный по домену экстент реакции: ядро
  отдаёт его срезом, хост сводит редукцией в фазе LEDGER. `Ξ` — **не канал**, реестр
  `ledger::Channel` замкнут шестью именами. У энергии наоборот: химическая энергия
  веществ стоит **слева**, поэтому реакция не источник, а перекладывание, и сохранение
  выходит по построению, а не проверкой. Каждый процесс обязан декларировать, сохраняет
  он величину, меняет через канал или превращает (`Conservation::Transmutes`).
  Счётчики каналов — `i128`, той же ширины, что доменная сумма (ADR-083).
- **Целые количества** (ADR-004, ADR-026). Количества веществ, энергия и объёмы — целые;
  единица учёта вещества молярная, `units_per_mol`. Килограммы остаются только в
  плотности, объёме и оседании. Float допустим для параметров и производных величин.
  Масштаб и разрядность хранения (`i32`/`i64`) не назначаются, а выводятся при загрузке
  из объявленных типичной и предельной концентраций (ADR-039, ADR-040).
- **Химия проверяется при загрузке** (ADR-025, ADR-027). Вещество объявляет состав по
  сохраняемым величинам (`conserved`, по умолчанию C, N, P, S, Fe). Реакция, не
  сходящаяся по любой из них или по энергии, — ошибка загрузки, а не предупреждение.
  Реакция совершает целое число квантов экстента `ξ`; всё округление и всё ограничение
  по субстрату происходит над `ξ`, а не над отдельными веществами. Размер кванта задаёт
  самый дефицитный участник реакции, а не самый обильный (ADR-039).
- **Потоковые схемы** (ADR-005, ADR-030). Донорно-акцепторный поток через грань: вычли у
  донора, прибавили акцептору. Сохранение точное по построению, а не приближённое.
  Semi-Lagrangian отвергнут. При загрузке конфига проверяется условие Куранта и выводится
  число подшагов диффузии `n = ⌈6·D·dt/dx²⌉`; `every_n_ticks > 1` для диффузионного поля
  запрещён — пропуск тиков умножает эффективный `dt`.
- **Форма ядра под WGSL** (ADR-015). Ядро — функция над плоскими массивами с независимой
  обработкой вокселя, переводимая в WGSL построчно. Внутри запрещены указатели,
  интерфейсы и аллокации в цикле. CPU-версия — вечный эталон, после порта не выбрасывается.
- **Никаких голых операторов над `Q`** (ADR-022). Только обёртки `qmul`, `qdiv`, `qadd`,
  `qsub`, `qexp`, … Трансцендентные функции — таблицами, не библиотечными вызовами.
  Детали и таблица операций — `docs/NUMERIC.md`.
- **Новое вещество добавляется правкой TOML** (ADR-018). Реестры веществ, реакций и
  процессов — по-настоящему данные. Если для нового сценария приходится трогать Rust,
  это дефект архитектуры, а не задача сценария.

## Команды

```
cargo build --workspace                              сборка
cargo test --workspace                               тесты
cargo clippy --workspace --all-targets -- -D warnings   линт
cargo fmt --all --check                              формат
python3 scripts/check_bare_q.py                      голые операторы над Q
scripts/test-hooks.sh                                тесты хуков
cargo run -p liminis -- run --config configs/scenarios/hello.toml --seed 42
```

Посмотреть на мир — `serve`, вьюер на локальном порту (ADR-070):

```
cargo run --release -p liminis -- serve \
    --config configs/scenarios/h2s-oxidation.toml --seed 42
```

`--release` здесь не украшение: в отладочной сборке тик идёт секунды, и это
важная разница в производительности. Есть и различие в проверках: фаза LEDGER стоит под
`cfg(debug_assertions)`, то есть **невязка проверяется только в ней**.

Тулчейн закреплён в `rust-toolchain.toml` и входит в воспроизводимость наравне с
сидом и конфигом (ADR-024).

Правка `configs/**`, `crates/liminis-core/src/kernels/**`,
`crates/liminis-core/src/process/**` (порядок процессов — семантика мира, ADR-036),
`crates/liminis-core/src/worldgen/**` или `crates/liminis-core/src/numeric/rng.rs`
без инкремента `WORLD_FORMAT_VERSION` в `crates/liminis-core/src/version.rs`
роняет CI (ADR-020). Образец сторожа — в `.github/workflows/ci.yml`; `config/`
в него **не входит**, и это причина, по которой семантике мира там не место.

Побочные находки фиксируй и проверяй по разделу «Побочные находки» в
[agent-development](docs/agent-development.md); они не расширяют текущий scope.
